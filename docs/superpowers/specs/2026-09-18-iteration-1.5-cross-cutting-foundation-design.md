# Iteration 1.5 — 跨切面基建 Spec

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this spec task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 MVP 骨架之上落地三个跨切面能力：event outbox (C1) + 状态机配置化 (C2) + 审批流 (C4)，并以 SysCountry 作为首个状态机迁移案例。

**Architecture:** 新增 Maven module `lumen-extension`（在 `lumen-parent/` 下），承载三个 sub-package `outbox`/`state`/`approval`。三者内部互依：state 引擎发事件 → outbox；approval 发事件 → outbox。每个能力都是"表 + 服务 + 异步消费者"。Caffeine 缓存 + `@Scheduled` 轮询 + `@Async` + `@TransactionalEventListener(AFTER_COMMIT)`。

**Tech Stack:** Spring Boot 3.2.5、MyBatis-Plus 3.5.7、Flyway、testcontainers (MySQL 8.0 + Redis 7)、Caffeine 3.x。

## 1. 背景与目标

### 1.1 当前现状

MVP 骨架（commit `174d951`）已完成：
- 6 个 module：common / rbac / masterdata / numbering / notification / bootstrap
- 6 张迁移表（V1-V6）：audit / login / RBAC / masterdata demo / numbering / notification + permission fix
- 7 个 admin 前端页面 + Login
- 10 个集成测试覆盖 8 个必测场景
- JWT dual-token + 多租户 + 审计 + 编号生成 + 通知 mock channels

### 1.2 缺口

业务文档（13 份 `*-v4.0`）已经写到字段/状态机/API 的颗粒度，但全部是 design-only，没有任何 `t_*` 业务表迁移过。如果直接进入 Iteration 2 业务模块（如委托单），会反复经历：
- 业务实体状态机代码硬编 → 状态变更需发代码
- 跨模块事件没有标准化通道 → 业务事务与消息发送不一致
- 审批没有通用通道 → 每个业务模块自己造

### 1.3 目标

落地三个跨切面能力，使 Iteration 2+ 每个业务模块：
- 状态机直接查表 → 改状态不动码
- 业务事件统一走 outbox → 不丢消息、不重复发送
- 审批调用通用 service → 不用每个模块造轮子

并通过 **SysCountry 作为首个迁移案例**验证整套机制。

### 1.4 不在范围内（推迟到 Iteration 2+）

- C3 RBAC 行级 / 字段级数据范围
- C5 SLA 规则引擎
- SpEL guard 表达式（`t_state_transition.guard_expression` 留 NULL）
- 审批多级链路（v1 单级）
- ApprovalRouter 走数据库（v1 yml 配置）
- Debezium CDC / Kafka / 分布式协调器
- 前端页面
- 对其他实体（Numbering / DictItem / NotificationTemplate）的 state-config 迁移

### 2.3 关键设计原则

1. **写 outbox 与业务事务同事务**：业务表 + outbox 行必须在同一个 `@Transactional` 中提交。消费是 AFTER_COMMIT 触发。
2. **Caffeine 缓存优先**：state-config 启动预热 + 30s TTL。DB 是真源，缓存是加速。
3. **`@Async` + `@TransactionalEventListener(AFTER_COMMIT)` 消费**：保证不回滚触发事件；保证不阻塞业务主线程。
4. **SysCountry 状态迁移是"零行为变化"**：删除 `CountryStateMachineConfig`（lumen-masterdata 现有硬编码类），改用查表；现有 `StateMachineIT` 测试行为不变。

### 3.4 Dispatcher（`@Scheduled` 轮询）

```java
@Component
@RequiredArgsConstructor
@ConditionalOnProperty(prefix = "lumen.outbox", name = "enabled", havingValue = "true", matchIfMissing = true)
public class OutboxDispatcher {
    private final EventOutboxMapper outboxMapper;
    private final ApplicationEventPublisher publisher;
    private final OutboxProperties props;

    @Scheduled(fixedDelayString = "${lumen.outbox.poll-interval-ms:2000}")
    @Transactional  // FOR UPDATE SKIP LOCKED 需要事务上下文
    public void dispatch() {
        // 1. 锁 + 取一批（锁持续到事务提交）
        List<EventOutbox> batch = outboxMapper.lockPendingBatch(props.getBatchSize());
        if (batch.isEmpty()) return;

        for (EventOutbox row : batch) {
            try {
                DomainEvent event = parse(row.getPayload());
                publisher.publishEvent(event);  // 无活动事务 → @EventListener 立即同步派发；@Async 后切换线程
                row.setStatus(OutboxStatus.DONE);
                row.setProcessedAt(LocalDateTime.now());
            } catch (Exception ex) {
                row.setRetryCount(row.getRetryCount() + 1);
                row.setLastError(ex.getMessage());
                if (row.getRetryCount() >= row.getMaxRetries()) {
                    row.setStatus(OutboxStatus.DEAD_LETTER);
                } else {
                    row.setStatus(OutboxStatus.PENDING);
                    row.setNextRetryAt(LocalDateTime.now().plusSeconds(backoffSeconds(row.getRetryCount())));
                }
            }
            try {
                outboxMapper.updateById(row);  // 单独 try，避免 updateById 失败吃掉重试
            } catch (Exception updateEx) {
                log.error("Failed to update outbox row {} status", row.getId(), updateEx);
            }
        }
    }

    private long backoffSeconds(int retryCount) {
        return switch (retryCount) {
            case 1 -> 30L;
            case 2 -> 120L;
            default -> 600L;
        };
    }
}
```

Mapper 上的锁查询：

```java
public interface EventOutboxMapper extends BaseMapper<EventOutbox> {
```

### 3.5 异步消费模板

> **关键**：outbox 消费者必须使用 **plain `@EventListener` + `@Async`**，**不要**使用 `@TransactionalEventListener(AFTER_COMMIT)`。
> 原因：OutboxDispatcher 是 `@Transactional` 但 `publishEvent` 已在循环内执行，监听器若依赖 AFTER_COMMIT 会在 dispatcher 事务尚未提交前触发，或因事务回滚而漏发。outbox 行的存在已经证明业务事务已提交，所以 plain `@EventListener` 即可。

```java
@Component
@RequiredArgsConstructor
public class SomeAsyncListener {
    @Async("outboxExecutor")
    @EventListener
    public void on(CountryStateChangedEvent event) {
        // 这里抛异常会触发 outbox 重试（OutboxDispatcher 捕获）
        doSomething(event);
    }
}
```

`@EnableAsync` 配置（放在 `lumen-bootstrap` 的 `AsyncConfig`）：

```java
@Configuration
@EnableAsync
public class AsyncConfig {
    @Bean("outboxExecutor")
    public Executor outboxExecutor() {
        ThreadPoolTaskExecutor exec = new ThreadPoolTaskExecutor();
        exec.setCorePoolSize(2);
        exec.setMaxPoolSize(8);
        exec.setQueueCapacity(200);
        exec.setThreadNamePrefix("outbox-");
        exec.initialize();
        return exec;
    }
}
```

> 例外：若业务模块想在**自己的事务内**对同一事件做同步反应（不等 outbox），可在 `eventBus.publish()` 同模块用 `@TransactionalEventListener(AFTER_COMMIT)`。这种用法只对同模块同步消费者有效。

Registry 关键代码：

```java
@Component
@RequiredArgsConstructor
public class StateMachineRegistry {
    private final StateTransitionMapper mapper;
    private final StateMachineProperties props;
    private Cache<String, Map<String, List<StateTransition>>> cache;

    @PostConstruct
    public void init() {
        cache = Caffeine.newBuilder()
                .expireAfterWrite(props.getCache().getTtlSeconds(), TimeUnit.SECONDS)
                .maximumSize(props.getCache().getMaxSize())
                .build();
    }

    @EventListener(ApplicationReadyEvent.class)
    public void warmup() { cache.invalidateAll(); }

    public Map<String, List<StateTransition>> getTransitions(String code) {
        return cache.get(code, this::loadFromDb);
    }

    private Map<String, List<StateTransition>> loadFromDb(String code) {
        List<StateTransition> rows = mapper.selectList(
            Wrappers.<StateTransition>lambdaQuery()
                .eq(StateTransition::getStateMachineCode, code)
                .eq(StateTransition::getDeleted, 0)
                .orderByAsc(StateTransition::getSortOrder)
        );
        return rows.stream().collect(Collectors.groupingBy(StateTransition::getFromState));
    }

    public void invalidate(String code) { cache.invalidate(code); }
}
```

Engine API：

```java
@Component
@RequiredArgsConstructor
public class StateMachineEngine {
    private final StateMachineRegistry registry;

    public void assertTransition(String code, String fromState, String toState) {
        List<StateTransition> transitions = registry.getTransitions(code).getOrDefault(fromState, List.of());
        boolean allowed = transitions.stream().anyMatch(t -> Objects.equals(t.getToState(), toState));
        if (!allowed) {
            throw new StateMachineException(
                String.format("状态机 %s 不允许从 %s 转移到 %s", code, fromState, toState)
            );
        }
    }

    public List<String> allowedNext(String code, String fromState) {
        List<StateTransition> transitions = registry.getTransitions(code).getOrDefault(fromState, List.of());
        return transitions.stream().map(StateTransition::getToState).distinct().toList();
    }
}
```

### 5.4 Service API

```java
@Service
@RequiredArgsConstructor
public class ApprovalService {
    private final ApprovalRecordMapper mapper;
    private final ApprovalRouter router;
    private final EventBus eventBus;

    @Transactional
    public ApprovalRecord submit(SubmitApprovalRequest req) {
        List<ApprovalChainConfig> chain = router.getChain(req.bizType());
        if (chain.isEmpty()) throw new ApprovalException("Unknown bizType: " + req.bizType());

        ApprovalChainConfig level = chain.get(0);  // v1 单级
        ApprovalRecord record = new ApprovalRecord();
        record.setBizType(req.bizType());
        record.setBizId(req.bizId());
        record.setTenantId(TenantContext.get());
        record.setLevel(level.getLevel());
        record.setStatus(ApprovalStatus.PENDING);
        record.setApplicantId(req.applicantId());
        record.setApprovalRole(level.getRole());
        record.setPayload(JsonUtil.toJson(req.payload()));
        record.setComment(req.comment());
        mapper.insert(record);

        eventBus.publish(new CountryEditSubmittedEvent(
            record.getId(), Long.valueOf(req.bizId()), req.applicantId()
        ));
        return record;
    }

    @Transactional
    public void approve(Long approvalId, Long approverId, String comment) {
        ApprovalRecord record = mapper.selectById(approvalId);
        if (record == null) throw new ApprovalException("Approval not found");
        if (record.getStatus() != ApprovalStatus.PENDING) throw new ApprovalException("Not pending");
        if (!hasRole(approverId, record.getApprovalRole())) throw new ApprovalException("No permission");

        record.setStatus(ApprovalStatus.APPROVED);
        record.setApproverId(approverId);
        record.setComment(comment);
        record.setDecidedAt(LocalDateTime.now());
        mapper.updateById(record);

        eventBus.publish(new CountryEditApprovedEvent(
            record.getId(),
            Long.valueOf(record.getBizId()),
            approverId,
            record.getApplicantId(),
            record.getPayload()
        ));
    }

    @Transactional
    public void reject(Long approvalId, Long approverId, String reason) {
        ApprovalRecord record = mapper.selectById(approvalId);
        if (record == null) throw new ApprovalException("Approval not found");
        if (record.getStatus() != ApprovalStatus.PENDING) throw new ApprovalException("Not pending");
        if (!hasRole(approverId, record.getApprovalRole())) throw new ApprovalException("No permission");

        record.setStatus(ApprovalStatus.REJECTED);
        record.setApproverId(approverId);
        record.setComment(reason);
        record.setDecidedAt(LocalDateTime.now());
        mapper.updateById(record);

        eventBus.publish(new CountryEditRejectedEvent(
            record.getId(), Long.valueOf(record.getBizId()), approverId, reason
        ));
    }

    @Transactional
    public void withdraw(Long approvalId, Long applicantId) {
        ApprovalRecord record = mapper.selectById(approvalId);
        if (record == null) throw new ApprovalException("Approval not found");
        if (!Objects.equals(record.getApplicantId(), applicantId)) throw new ApprovalException("Only applicant can withdraw");
        if (record.getStatus() != ApprovalStatus.PENDING) throw new ApprovalException("Not pending");

        record.setStatus(ApprovalStatus.WITHDRAWN);
        record.setDecidedAt(LocalDateTime.now());
        mapper.updateById(record);
    }

    private boolean hasRole(Long userId, String roleCode) {
        // 调 lumen-rbac 的 PermissionService 或 SysUserRoleMapper 查询
        // v1 简化：直接调 PermissionService.userHasRole(userId, roleCode)
        return permissionService.userHasRole(TenantContext.get(), userId, roleCode);
    }
}
```

## 9. 性能与扩展性

- **Outbox 吞吐**：单实例 dispatcher 2s 轮询 × batch=50 = ~25 events/s。多实例线性扩展（`FOR UPDATE SKIP LOCKED` 兜底）。
- **State-config 缓存**：Caffeine 30s TTL，启动预热。常见查询 <1ms。Iteration 2 加 `/admin/cache/state-machine/refresh` 端点手动 invalidate。
- **SysCountry 状态迁移并发**：单 service 内 `@Transactional`，`@Version` 乐观锁保护并发更新。
- **MySQL 8.0+ 强制**：compose/IT 容器都是 8.0；production README 标注。

## 10. 风险与缓解

| 风险 | 缓解 |
|------|------|
| SysCountry 状态机迁移影响现有 StateMachineIT | 迁移前后各跑一次 StateMachineIT；保留 lumen-common 内置状态机类（不删） |
| `FOR UPDATE SKIP LOCKED` 需要 MySQL 8.0+ | compose/IT 用 8.0；README 标注 production MySQL 5.7 会失败 |
| 事件消费 eventual consistency | 重试 3 次 + 死信兜底；业务调用方应理解为"事务内可见、跨模块后续可见" |
| Caffeine 30s TTL 滞后 | Iteration 2 加 manual invalidate 端点；当前靠 TTL 自然刷新 |
| 异步消费不阻塞主线程但失败不立即反馈 | 重试 + 死信 + 监控死信表（README 给查询 SQL） |
| lumen-extension 反向依赖 lumen-masterdata | 不会发生 —— lumen-extension 只依赖 lumen-common |
| SysCountry edit 入口未上 frontend | 前端推到 Iteration 2；本期仅 API + IT 验证 |
| `@TransactionalEventListener(AFTER_COMMIT)` 与无事务 dispatcher 不兼容 | 见 §3.5：消费端用 plain `@EventListener` + `@Async`；AFTER_COMMIT 只在同事务同模块同步反应时用 |
