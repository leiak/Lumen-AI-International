## 1. 目标与边界

**目标**：在 Lumen 平台补齐末端派送履约层，把 WMS 出库 SHIPPED 事件翻译为"派车 + 装载 + 在途 + 签收"闭环，并支撑车辆利用率仪表盘。

**属于本切片**：
- 配送订单（`t_delivery_order`）端到端状态机
- 运力资源（车辆/司机/承运人）masterdata + 车辆状态机
- 排线引擎（mock nearest-neighbor，无地图 API）
- 配载校验（按车型 max_load_kg/volume_m3 + 订单总重/总体积）
- 派车占位 + 装载/在途/签收回执
- 异常工单（拒收/超时/货损/地址错）
- 车辆利用率（按日聚合 + 仪表盘数据源）
- WMS `outbound.shipped` 事件订阅 → 自动建配送订单

**不属于本切片**：
- 真实地图/TSP（mapbox/amap/google）— V5 EP-D1 接入
- OCR / 电子签收 — V5 EP-2 接入
- 末端费用与 10-财务联动 — 4.3+ 再做
- 多承运人/多车队竞价 — V5+

## 3. 数据模型（V19）

| 表 | 关键列 | 备注 |
|----|--------|------|
| `wms_vehicle` | id, tenant_id, plate_no, type, max_load_kg, max_volume_m3, status (VEHICLE state machine), driver_id | 车辆主数据；status 用 TYPE 列覆盖 @TableLogic |
| `wms_driver` | id, tenant_id, name, phone, license_no, status (ACTIVE/SUSPENDED) | 司机主数据 |
| `wms_carrier` | id, tenant_id, code, name, contact, status | 承运人主数据（自有车队 vs 外协） |
| `wms_delivery_order` | id, tenant_id, no, source_no (from outbound), source_type (OUTBOUND), status, vehicle_id, driver_id, planned_depart_at, actual_depart_at, arrived_at, delivered_at, total_weight_kg, total_volume_m3, stop_count, sign_required, remark | 配送订单聚合根 |
| `wms_delivery_stop` | id, tenant_id, order_id, stop_no, address, contact_name, contact_phone, planned_at, arrived_at, completed_at, status (PENDING/ARRIVED/COMPLETED/FAILED), failure_reason, sign_photo_url | 配送站点（一个订单多个，依次访问） |
| `wms_delivery_line` | id, tenant_id, order_id, item_id, qty, weight_kg, volume_m3 | 配送明细（与 outbound line 对应） |
| `wms_delivery_exception` | id, tenant_id, order_id, type (REJECTED/OVERTIME/DAMAGE/ADDR_ERR), status (OPEN/INVESTIGATING/RESOLVED/CLOSED), description, handler, resolved_at | 异常工单 |

DB CHECK：
- `wms_delivery_order`: `total_weight_kg >= 0`, `total_volume_m3 >= 0`, `stop_count >= 1`
- `wms_delivery_stop`: `stop_no >= 1`, `status IN ('PENDING','ARRIVED','COMPLETED','FAILED')`
- `wms_vehicle`: `max_load_kg > 0`, `max_volume_m3 > 0`

## 4. 状态机（V20 seed）

3 个状态机 = 18 transitions：

| SM | transitions | 角色门控 |
|----|-------------|----------|
| `DISPATCH_ORDER` | 7 | dispatcher / driver |
| `VEHICLE` | 6 | dispatcher / dispatch_admin |
| `EXCEPTION_WORK_ORDER` | 5 | customer_service / dispatch_admin |

transition 名 → 对应 service 方法：
- `DISPATCH_ORDER`: `assign` (PENDING_DISPATCH→DISPATCHED), `load` (→LOADED), `depart` (→ENROUTE), `arrive` (→ARRIVED), `sign` (→SIGNED), `cancel` (→CANCELLED, any non-terminal), `exception` (→EXCEPTION)
- `VEHICLE`: `dispatch`, `load`, `depart`, `returning`, `idle`, `out`
- `EXCEPTION_WORK_ORDER`: `investigate`, `resolve`, `close`, `reopen`, `cancel`

## 5. 排线/配载引擎

### 5.1 RoutingEngine（mock NN）

```java
public interface RoutingEngine {
  /**
   * 输入站点列表 + 起始仓地址 → 返回访问顺序.
   * Mock 实现: 按 stop_no 顺序返回 (无 WS 优化). EP-D1 接口保留.
   */
  List<Long> plan(Long warehouseId, List<DeliveryStop> stops);
}
```

实现类 `MockRoutingEngine` — 不依赖地图；留 `RouteEngineProperties.routeEngine = "map" 单独启真实 TSP` 入口。

### 5.2 LoadingValidator

```java
public interface LoadingValidator {
  /**
   * 校验 车辆适配车序/载重/体积.
   * 抛 InsufficientVehicleException if over capacity.
   */
  void validate(WmsVehicle vehicle, DeliveryOrder order);
}
```

规则：
- `order.total_weight_kg <= vehicle.max_load_kg` 否则越线
- `order.total_volume_m3 <= vehicle.max_volume_m3` 否则越线
- `order.stop_count <= dlv.max_stop_per_vehicle` (configurable, default 30)

## 6. 事件进出

**发布**（WMS 已有的 outbox 模式）：
- `DeliveryOrderCreatedEvent` → 财务/通知模块订阅（V5 接入）
- `DeliveryDispatchedEvent` → 司机手持/IoT（V5）
- `DeliverySignedEvent` → 财务末端费/通知/Vehicle.idle 触发
- `DeliveryExceptionEvent` → 客服工单/异常模块

**订阅**（V21-22 PR5 实现）：
- `OutboundShippedEvent` (WMS outbound.shipped) → 自动建 `DeliveryOrder` (PENDING_DISPATCH)，从 outbound line 复制 item/qty/weight/volume，address 取自 `wms_customer` 的 primary address

订阅器实现：`WmsOutboundShippedListener`（`@Async("outboxExecutor") @EventListener`）— 遵循现有 lumen-extension/outbox 模式。

## 7. 关键 Service

### 7.1 DeliveryOrderService（CRUD + 状态机）
- `create(req)` / `get(id)` / `list(params)` / `update(id, req)` — 基础 CRUD
- `assign(orderId, vehicleId, driverId)` — 派车占位 + LoadingValidator 校验
- `load(orderId)` — 装载（接收起点回执）
- `depart(orderId)` — 出发
- `arrive(orderId, stopId)` — 到达某站
- `sign(orderId, signPhotoUrl)` — 签收
- `cancel(orderId, reason)` — 撤销
- `raiseException(orderId, type, description)` — 转异常工单

### 7.2 DispatchEngine（编排）
- `autoAssign(orderId)` — 自动派车（按车型匹配 → 同租户最近的）
- `disposeException(exceptionId)` — 处理异常工单

### 7.3 VehicleUtilizationQuery（只读）
- `dailyUtilization(daily, vehicleId?)` — 车辆利用率日聚合

### 7.4 ExceptionService（工单流转）
- `create(orderId, type, desc)` / `investigate(id, handler)` / `resolve(id, action)` / `close(id)` / `reopen(id, reason)`
