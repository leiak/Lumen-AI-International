## 1. 目标与边界

**目标**：在 lumen 平台补齐客服中心纵切片，给 4.1 的异常工单加上「时间 + 严重度 + 业务时间」三维度的 SLA 规则、按 tenant 可配置的目标时长、自动三级升级（客服 → 主管 → 经理）。

**属于本切片**：
- `lumen-cs` Maven 子模块（独立 boot classpath，共享 `lumen-common` / `lumen-extension` 基础设施）
- 4 张新业务表（V24 migration）：`t_sla_config` / `t_business_calendar` / `t_holiday` / `t_sla_event`
- 5 个 service：`SlaConfigService` / `BusinessCalendarService` / `HolidayService` / `SlaEventService` / `EscalationService`
- 1 个纯函数 `SlaCalculator`（业务时间算法）
- 1 个 `SlaEscalationScheduler`（5min @Scheduled 轮询）
- 跨模块事件：lumen-cs 订阅 `DeliveryExceptionStateChangedEvent`（lumen-dispatch 已发布）+ lumen-cs 发布 `ExceptionEscalatedEvent`（lumen-dispatch 订阅）
- 6 个新角色 + 5 个新权限（V25 seed）
- 4 个 FE 页面（3 配置页 + 1 SLA 视角异常列表）+ 3 共享组件

**不属于本切片**：
- 暂停 / 恢复 SLA 计时（4.2.x follow-up）
- 客户等级动态 SLA（V5+）
- 真实邮件 / 短信通知（用 outbox 事件，订阅方 V5+ 实现）
- 多租户日历导入 / 同步
- per-tenant 自定义 type→severity 映射（用硬编码映射）
- 工单聊天 / WS 实时通讯（V5+）

## 3. 数据模型（V24 migration，lumen-cs）

### 3.1 `t_sla_config` — SLA 配置（per-tenant, per-severity, per-level）

```sql
CREATE TABLE t_sla_config (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  tenant_id BIGINT NOT NULL,
  severity VARCHAR(16) NOT NULL,        -- HIGH / MEDIUM / LOW
  level VARCHAR(16) NOT NULL,            -- L1 / L2 / L3
  response_minutes INT NOT NULL,         -- 响应门槛（业务分钟）
  resolve_minutes INT NOT NULL,          -- 解决门槛（业务分钟）
  escalate_to_level VARCHAR(16),         -- 超过 resolve 后升级到 L? (NULL = 不升)
  created_at DATETIME(3) NOT NULL,
  updated_at DATETIME(3) NOT NULL,
  deleted TINYINT NOT NULL DEFAULT 0,
  version INT NOT NULL DEFAULT 0,
  UNIQUE KEY uk_tenant_severity_level (tenant_id, severity, level, deleted)
);
```

### 3.2 `t_business_calendar` — 业务时间（per-tenant, per-weekday, 多段）

```sql
CREATE TABLE t_business_calendar (
  id BIGINT PRIMARY KEY,
  tenant_id BIGINT NOT NULL,
  weekday TINYINT NOT NULL,              -- 1=周一 ... 7=周日（ISO）
  start_time TIME NOT NULL,
  end_time TIME NOT NULL,
  created_at, updated_at, deleted, version,
  UNIQUE KEY uk_tenant_weekday_start (tenant_id, weekday, start_time, deleted)
);
```

### 3.3 `t_holiday` — 节假日（per-tenant）

```sql
CREATE TABLE t_holiday (
  id BIGINT PRIMARY KEY,
  tenant_id BIGINT NOT NULL,
  holiday_date DATE NOT NULL,
  description VARCHAR(128),
  created_at, updated_at, deleted, version,
  UNIQUE KEY uk_tenant_date (tenant_id, holiday_date, deleted)

```

### 3.4 `t_sla_event` — SLA 事件审计

```sql
CREATE TABLE t_sla_event (
  id BIGINT PRIMARY KEY,
  tenant_id BIGINT NOT NULL,
  exception_id BIGINT NOT NULL,
  event_type VARCHAR(32) NOT NULL,       -- L1_RESPONSE_DUE / L1_RESPONDED / ESCALATED / RESOLVED
  current_level VARCHAR(16) NOT NULL,    -- 升级前 level
  severity VARCHAR(16) NOT NULL,
  occurred_at DATETIME(3) NOT NULL,      -- 业务时间发生时刻
  payload JSON,                          -- escalated_to, minutes_overdue, business_minutes_elapsed, etc.
  created_at DATETIME(3) NOT NULL,
  deleted TINYINT NOT NULL DEFAULT 0,
  version INT NOT NULL DEFAULT 0,
  KEY idx_exception (exception_id),
  KEY idx_tenant_occurred (tenant_id, occurred_at),
  -- 防并发重复升级：同一 exception 同一升级目标只能有 1 行
  UNIQUE KEY uk_exception_event_target (exception_id, event_type, current_level, deleted)
);
```

## 4. 状态机

### 4.1 现有 4.1 EXCEPTION_WORK_ORDER（**不修改**）

5 个 transitions 已在 V20 seed：
- `investigate` (OPEN→INVESTIGATING)
- `resolve` (INVESTIGATING→RESOLVED)
- `close` (RESOLVED→CLOSED)
- `reopen` (CLOSED→OPEN)
- `cancel` (any non-terminal→CANCELLED)

### 4.2 升级是**跨 transition 触发**而非新 transition

升级不通过 `t_state_transition` 新增 action 实现，而是：
1. `EscalationService.scan()` 检测到 SLA breach
2. 直接 UPDATE `WmsDeliveryException.handler` 到新角色对应 user（按 tenant 选第一个匹配 user）
3. 写 `t_sla_event` (ESCALATED)
4. 发 `ExceptionEscalatedEvent` → lumen-dispatch 监听器同步 handler 字段 + 写 audit log

这样的好处：state machine 保持 5 transitions 不变，guard 表达式只改 investigate 时的角色校验。

### 4.3 现有 guard 表达式升级（V25 lumen-dispatch migration）

`EXCEPTION_WORK_ORDER` 的 guard 改成**按当前 level 校验角色**：

```sql
-- investigate (OPEN→INVESTIGATING)：L1 必为 customer_service
UPDATE t_state_transition
SET guard_expression = 'role:customer_service OR (role:cs_supervisor AND level:L1) OR (role:cs_manager AND level:L1)'
WHERE state_machine_code = 'EXCEPTION_WORK_ORDER' AND transition_name = 'investigate';

-- resolve (INVESTIGATING→RESOLVED)：当前 handler 角色必须 ≥ L1
UPDATE t_state_transition
SET guard_expression = 'role:customer_service OR role:cs_supervisor OR role:cs_manager'
WHERE state_machine_code = 'EXCEPTION_WORK_ORDER' AND transition_name = 'resolve';
```

> 当前 handler 角色由 lumen-cs 升级链路写入；guard 表达式不需要包含 level，因为 handler 已经被前置保证。

## 5. 核心 Service

### 5.1 SlaCalculator（纯函数，单元测试覆盖）

```java
public class SlaCalculator {
    /**
     * 计算 [from, to] 之间「业务分钟数」。
     *
     * <p>算法：按天迭代，节假日/非工作日跳过；首末日按时间戳比例算。
     * 单次调用 O(days)，30 天范围 ~30 次循环，< 1ms。
     */
    long businessMinutes(TenantCalendar cal, LocalDateTime from, LocalDateTime to);
}
```

`TenantCalendar` 是 in-memory DTO（按 tenant 加载 `t_business_calendar` + `t_holiday`），由 `BusinessCalendarService.load(tenantId)` 提供。

测试覆盖（12 cases）：
- 同一工作日 9-18 完整 8h
- 部分工作日（10-12 = 120min）
- 跨午夜（周一 22:00 → 周二 10:00 = 120min）
- 节假日跳过
- 周末跳过
- 多段时段（午休拆 9-12 + 13-18）
- 跨年 / 闰秒
- to ≤ from 返回 0
- 跨 30 天
- 跨年
- DST（中国无 DST，placeholder case）
- 租户无 calendar（fallback 9-18 周一-五）

### 5.2 EscalationService 升级算法

```java
@Service
public class EscalationService {
    
    @Scheduled(fixedDelay = 300_000)  // 5min
    public void scan() {
        // 1. 查所有 status IN (OPEN, INVESTIGATING) 的 exception
        // 2. 对每条：
        //    a. 查 t_sla_event 找最后一次 L1_RESPONDED 事件（resolve 计时起点）
        //       若没有，用 exception.created_at 作为兜底起点
        //    b. 查 t_sla_config (tenant, severity, current_level) → resolve_minutes
        //    c. elapsed = SlaCalculator.businessMinutes(cal, start, now)
        //    d. 若 elapsed > resolve_minutes AND escalate_to_level != null：
        //       - 写 t_sla_event (ESCALATED, current_level = fromLevel)
        //         UNIQUE KEY uk_exception_event_target 防并发重复
        //       - 发 outbox ExceptionEscalatedEvent(
        //           exceptionId, fromLevel, toLevel, severity,
        //           businessMinutesElapsed, newHandlerUsername)
    }
}
```

> **L1_RESPONDED 写入时机**：由 §5.3 `DeliveryExceptionStateChangedEventListener` 在 `toState=INVESTIGATING` 时写入（即首次 investigate 成功 = L1 接单响应）。EscalationService 只需读该事件，不写。

### 5.3 DeliveryExceptionStateChangedEvent 监听器（lumen-cs）

```java
@Component
public class DeliveryExceptionStateChangedEventListener {
    
    @EventListener
    @Async("outboxExecutor")
    public void onExceptionTransitioned(DeliveryExceptionStateChangedEvent e) {
        switch (e.getToState()) {
            case "OPEN" -> slaEventService.record(e.getExceptionId(), "L1_RESPONSE_DUE", ...);
            case "INVESTIGATING" -> slaEventService.record(e.getExceptionId(), "L1_RESPONDED", ...);
            case "RESOLVED", "CLOSED" -> slaEventService.record(e.getExceptionId(), "RESOLVED", ...);
            // CANCELLED: 写 t_sla_event CANCELLED — 终止 SLA 计时
        }
    }
}
```

> 设计要点：所有 SLA 计时事件由**单一** listener 根据 `toState` 分支写入，避免多个 listener 写同一张表造成 race / 重复。监听器是 idempotent 的（依赖 `t_sla_event.UNIQUE KEY uk_exception_event_target` 防重复）。

### 5.4 跨模块事件：ExceptionEscalatedEvent

```java
public class ExceptionEscalatedEvent extends DomainEvent {
    private final Long exceptionId;
    private final Long tenantId;
    private final String fromLevel;       // L1
    private final String toLevel;         // L2
    private final String severity;        // HIGH
    private final Long businessMinutesElapsed;
    private final String newHandlerUsername;  // 新角色对应 user (e.g. "alice@cs_supervisor")
    // ... @JsonCreator 构造器
}
```

通过 `DomainEventTypeRegistrar` SPI 注册（复用 4.1.x 修复后的机制）：

```java
// lumen-cs/event/CsEventTypeRegistrar.java
@Component
public class CsEventTypeRegistrar implements DomainEventTypeRegistrar {
    @Override
    public Map<String, Class<? extends DomainEvent>> registeredTypes() {
        return Map.of("exception.escalated", ExceptionEscalatedEvent.class);
    }
}
```

### 5.5 lumen-dispatch 监听 ExceptionEscalatedEvent

```java
// lumen-dispatch/listener/ExceptionEscalatedEventListener.java
@Component
public class ExceptionEscalatedEventListener {
    @EventListener
    @Async("outboxExecutor")
    public void onEscalated(ExceptionEscalatedEvent e) {
        WmsDeliveryException ex = exceptionMapper.selectById(e.getExceptionId());
        ex.setHandler(e.getNewHandlerUsername());
        exceptionMapper.updateById(ex);
        // 同步写 audit log（dispatch 现有 audit 切面已自动捕获 handler 变更）
    }
}
```
