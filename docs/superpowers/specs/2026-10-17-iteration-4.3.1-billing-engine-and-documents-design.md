# Iteration 4.3.1 — 末端费用计费引擎 + 单据基础（lumen-finance 模块雏形）

> **设计文档**，不是任务清单。任务级别（checkbox）按 PR 落到
> `docs/superpowers/plans/2026-10-17-iteration-4.3.1-billing-engine-and-documents.md` 时再细化。
>
> 4.3 全栈设计分为 3 个 sub-iteration，本 spec 仅覆盖 **4.3.1 = 计费引擎 + 单据基础**。
> 多币种 (4.3.2) / ERP + 对账 + 报表 UI (4.3.3) 见后续 spec。

## 1. 目标与边界

**目标**：新建 `lumen-finance` Maven 子模块，实现基于 **Aviator 表达式** 的可配置计费引擎，
订阅上游业务事件（4.1 派车完成 / 3.0 WMS 入库出库完成）后自动写"暂估 + 应收/应付单据"，
支持业务初审（1 级审批） + 1 个最小报表页（应收清单），完成"业务完成 → 应收单可见"的最小闭环。

**属于本切片**：
- `lumen-finance` Maven 子模块（独立 boot classpath，第 10 子模块）
- 6 张新业务表（V26 migration）：`t_billing_rule` / `t_billing_rule_item` / `t_billing_event_log` / `t_billing_accrual` / `t_billing_invoice` / `t_billing_rule_audit`
- 1 个表达式引擎：`BillingScriptEngine`（Aviator 沙箱）
- 4 个 service：`BillingRuleService` / `BillingEngine` / `AccrualService` / `InvoiceService`
- 1 级审批（业务初审，状态机复用 lumen-dispatch 的 `StateMachineEngine`）
- 跨模块事件订阅：`delivery_order.state_changed` (toState=COMPLETED) + `wms_inbound.completed` + `wms_outbound.completed`
- V26 RBAC seed：2 个新角色（`finance_ops` + `finance_reviewer`）+ 6 个新权限
- 1 个 FE 页面（应收清单 + 业务初审工作台）
- 单币种 CNY（多币种留给 4.3.2）

**不属于本切片**（明确推迟到后续 sub-iteration）：
- 多币种 / 汇率 / 税率分离（4.3.2）
- 财务复核（2 级审批）（4.3.2）
- 调账单 / 反向冲销（4.3.2）
- 多 ERP Adapter（4.3.3）
- 月度账期 / 对账单 / 差异告警（4.3.3）
- 4 个剩余报表页（4.3.3）
- 历史业务数据回填
- 真实 ERP HTTP 集成

### 2.1 跨模块依赖（严格单向，禁止反向）

```
lumen-dispatch  ──delivery_order.state_changed(COMPLETED)──>  outbox
lumen-wms       ──wms_inbound.completed────────────────────>  outbox
lumen-wms       ──wms_outbound.completed───────────────────>  outbox
                          │
                          ▼
                  lumen-finance  BusinessEventListener
                          │
                  ① 写 t_billing_event_log (幂等)
                  ② 加载 t_billing_rule + t_billing_rule_item
                  ③ BillingScriptEngine.eval() 试算
                  ④ 写 t_billing_accrual (status=OPEN)
                          │
                  ─── 业务事件二次触发 (COMPLETED 锁定) ───
                          │
                  ⑤ accrual: OPEN → LOCKED
                  ⑥ 生成 t_billing_invoice (status=DRAFT, direction=RECEIVABLE/PAYABLE)
                          │
                  ─── 1 级审批 (业务初审) ───
                          │
                  ⑦ invoice: DRAFT → PENDING_L1 → L1_APPROVED
                          │
                  ─── 报表页 (4.3.1 范围末端) ───
                          │
                  ⑧ 应收清单 FE 列表
```

### 2.2 Maven 依赖方向

| 模块 | 依赖 | 反向依赖（禁止） |
|---|---|---|
| `lumen-finance` | `lumen-common`, `lumen-extension`, `lumen-rbac`, `lumen-masterdata` | (无 — lumen-finance 是叶子模块) |
| `lumen-dispatch` | `lumen-common`, `lumen-extension` | `lumen-finance` |
| `lumen-wms` | `lumen-common`, `lumen-extension` | `lumen-finance` |

**注**：lumen-finance **不直接依赖** lumen-dispatch / lumen-wms / lumen-cs；只通过
outbox 事件（lumen-extension 的 `DomainEventTypeRegistrar` + `ApplicationEventPublisher`）
订阅上游业务事件，反向不调任何上游 API。

### 2.3 与现有模块的契约点

| 契约 | 现有模块 | lumen-finance 消费方式 |
|---|---|---|
| `DeliveryOrderStateChangedEvent` | lumen-dispatch 4.1.x-PR2 | `BusinessEventListener.onDeliveryOrderCompleted()` |
| `WmsInboundCompletedEvent` | lumen-wms 3.0 | `BusinessEventListener.onInboundCompleted()` |
| `WmsOutboundCompletedEvent` | lumen-wms 3.0 | `BusinessEventListener.onOutboundCompleted()` |

## 4. 表达式引擎（Aviator 沙箱）

### 4.1 引擎接口

```java
public interface BillingScriptEngine {
  /**
   * 编译并缓存表达式。
   * @return 编译后的 Expression (Aviator) + 解析状态
   * @throws BillingExpressionException 编译失败 (语法错 / 引用未注册变量)
   */
  CompiledExpression compile(String expression);

  /**
   * 求值 (使用预编译的 Expression + 绑定变量环境)。
   * @throws BillingExpressionTimeoutException >100ms
   * @throws BillingExpressionException 运行时错 (除 0 / 变量未绑定)
   */
  BigDecimal eval(CompiledExpression compiled, Map<String, Object> env);

  /** 表达式求值总入口 (供 BillingEngine 调用, 内部 compile+cache+eval) */
  BigDecimal eval(String expression, Map<String, Object> env);
}
```

### 4.2 沙箱安全配置

```java
AviatorEvaluator evaluator = AviatorEvaluator.newInstance(new AviatorEvaluatorOptions()
    .setOption(Options.ALLOW_NULL_LITERAL, true)
    .setOption(Options.ALWAYS_PARSE_FLOATING_POINT_NUMBER_INTO_DECIMAL, true)
    // 关键: 禁用所有 Java 方法反射 + ClassLoader
    .setOption(Options.DISABLE_PROPERTY_SYNTAX, true)  // 仅用 a.b 不可, 须显式 env.get
    .setFunctionMethods(null)
    .setLoader(null));  // 禁止自定义 ClassLoader
```

**白名单输入变量**（规则表达式只能引用以下变量名）：

| 变量名 | 类型 | 来源 | 业务含义 |
|---|---|---|---|
| `amount` | BigDecimal | 业务事件 | 业务基础金额 |
| `weight` | BigDecimal | 业务事件 | 重量 (kg) |
| `distance` | BigDecimal | 业务事件 | 距离 (km) |
| `quantity` | int | 业务事件 | 件数 |
| `customer_level` | String | 客户表 | 客户等级 (NORMAL / VIP / VVIP) |
| `zone` | String | 地址字典 | 区域 (URBAN / SUBURBAN / REMOTE) |
| `service_type` | String | 业务事件 | 服务类型 (STANDARD / EXPRESS / SAME_DAY) |
| `is_weekend` | boolean | 业务事件 | 是否周末下单 |
| `is_holiday` | boolean | 节假日表 | 是否节假日 |

**禁止**：
- 任何 Java 方法调用 (反射 / 静态方法 / 实例方法)
- 任何文件系统访问 (`new File(...)` 等)
- 任何网络访问
- `System.exit` / `Runtime.exec`
- 反射 (`Class.forName`)

**测试覆盖**（沙箱逃逸测试）：
- `Class.forName("java.lang.Runtime").getMethod("exec", String.class).invoke(...)` → 抛 `BillingExpressionException`
- `new java.io.File("/etc/passwd")` → 抛 `BillingExpressionException`
- 引用未注册变量 `unknown_var` → 抛 `BillingExpressionException(UNKNOWN_VARIABLE)`
- 表达式求值耗时 >100ms (sleep 循环) → 抛 `BillingExpressionTimeoutException`

### 4.3 表达式示例

```javascript
// 基础费 + 距离 + 重量 + 节假日附加
base_amount: if (zone == "REMOTE") 50 else 30
distance_fee: distance * (service_type == "EXPRESS" ? 3.0 : 1.5)
weight_fee: weight * 2.0
weekend_extra: is_weekend || is_holiday ? (base_amount + distance_fee + weight_fee) * 0.2 : 0
gross_amount: base_amount + distance_fee + weight_fee + weekend_extra
```

3 个 rule_item 各自计算 `base_amount` / `distance_fee` / `weekend_extra`，最终由 `BillingEngine.aggregate()` 汇总。

### 4.4 表达式缓存

- 编译后按 `expression_hash` (SHA-256 normalized) 缓存到 `ConcurrentHashMap<String, CompiledExpression>`
- 进程内缓存，不持久化（重启后按需重新编译）
- 缓存大小上限 1000，超过 LRU 淘汰
- 编译失败时，标记 `t_billing_rule.status = INVALID` + 写 `t_billing_rule_audit`，不阻塞其他规则

## 5. 单据状态机（V26 seed，复用 `StateMachineEngine`）

### 5.1 状态定义

**`t_billing_invoice` 状态**：
```
DRAFT → PENDING_L1 → L1_APPROVED → PUSHED (4.3.3)
  │        │            │
  │        │            └── (4.3.2 加 PENDING_L2 → L2_APPROVED)
  │        └──reject──▶ REJECTED
  │                          │
  └──reject──▶ REJECTED      └──adjust──▶ ADJUSTED (4.3.2)
```

**`t_billing_accrual` 状态**：
```
OPEN → LOCKED → CONVERTED (产生 invoice)
  │      │
  │      └──release──▶ RELEASED
  └──failed──▶ OPEN_FAILED
```

### 5.2 V26 seed transitions (`lumen-bootstrap/src/main/resources/db/migration/V26__billing_state_transitions.sql`)

```sql

('billing_invoice', 'PENDING_L1',  'L1_APPROVED', 'l1_approve', 'finance_reviewer', NULL),
('billing_invoice', 'PENDING_L1',  'REJECTED',    'l1_reject',  'finance_reviewer', NULL),
('billing_invoice', 'DRAFT',       'REJECTED',    'reject',     'finance_ops',     NULL);
```

## 6. 跨模块事件流

### 6.1 上游事件订阅（3 个）

| 事件类型 | 触发点 | 业务类型 | direction | source_event_id 字段 |
|---|---|---|---|---|
| `DeliveryOrderStateChangedEvent` (toState=COMPLETED) | 4.1 lumen-dispatch `DeliveryOrderService.complete()` | LAST_MILE | RECEIVABLE | `event.eventId()` |
| `WmsInboundCompletedEvent` (待 3.0 确认事件名) | 3.0 lumen-wms | WAREHOUSE_IN | PAYABLE | `event.eventId()` |
| `WmsOutboundCompletedEvent` (待 3.0 确认事件名) | 3.0 lumen-wms | WAREHOUSE_OUT | PAYABLE | `event.eventId()` |

**前置依赖**：3.0 需确认/补齐 `WmsInboundCompletedEvent` / `WmsOutboundCompletedEvent`。
若 3.0 缺，4.3.1 临时从 `wms_inbound` / `wms_outbound` 表轮询（降级方案），4.3.2 改回事件。

### 6.2 下游事件发布（4.3.1 范围）

4.3.1 **不发布**任何下游事件（仅写表 + outbox row 可选）。下游订阅方（lumen-cs / lumen-notification）留待 4.3.2/4.3.3 或后续 iteration 接入。

### 6.3 事件处理时序

```
T0  业务事件 publish to outbox
T1  OutboxDispatcher 拉取 (≤2s 轮询) → publishEvent
T2  BusinessEventListener.onXxxCompleted(event)
    - 写 t_billing_event_log (UNIQUE 幂等, 重复则 noop)
    - 异步 @Async 调 BillingEngine.accrue(event)
T3  BillingEngine.accrue()
    - 加载 tenant 匹配 rules (按 priority ASC)
    - 编译 rule.expression (缓存)
    - 求值 → BigDecimal
    - aggregate() → gross/tax/net
    - 写 t_billing_accrual (UNIQUE 幂等, 重复则 noop)
T4  (后续) 业务事件再次 toState=COMPLETED_LOCKED (或显式 API)
    - AccrualService.finalize(accrualId)
    - accrual: OPEN → LOCKED
    - 生成 t_billing_invoice (DRAFT)
    - 调 InvoiceNumberingService 生成 invoice_no
T5  (人工) 财务 ops 提交 → PENDING_L1
T6  (人工) finance_reviewer 审批 → L1_APPROVED
```

## 8. REST API 设计（4.3.1 范围，~14 endpoints）

### 8.1 计费规则 (`/api/v1/finance/rules`)
- `GET /rules?businessType=&direction=&status=&pageNum=&pageSize=` — 分页查询
- `GET /rules/{id}` — 详情（含 rule_items）
- `POST /rules` — 新建（默认 DRAFT）
- `PUT /rules/{id}` — 更新（产生新 version + 写 audit）
- `POST /rules/{id}/activate` — DRAFT/INVALID → ACTIVE（编译全部 expression，失败回 INVALID）
- `POST /rules/{id}/disable` — ACTIVE → DISABLED

- `GET /accruals?businessType=&status=&pageNum=&pageSize=` — 分页
- `GET /accruals/{id}` — 详情
- `POST /accruals/{id}/finalize` — OPEN → LOCKED + 生成 invoice（仅 system/admin 可调）

### 8.3 单据 (`/api/v1/finance/invoices`)
- `GET /invoices?direction=&status=&counterpartyId=&pageNum=&pageSize=` — 分页
- `GET /invoices/{id}` — 详情
- `POST /invoices/{id}/submit` — DRAFT → PENDING_L1
- `POST /invoices/{id}/l1-approve` — PENDING_L1 → L1_APPROVED
- `POST /invoices/{id}/l1-reject` — PENDING_L1 → REJECTED (body: reason)

### 8.4 事件溯源 (`/api/v1/finance/events`)
- `GET /events?businessType=&processStatus=&pageNum=&pageSize=` — 仅 admin 可查

## 11. 错误处理

| 场景 | 行为 |
|---|---|
| Aviator 编译失败 | `rule.status = INVALID` + audit + 警告日志，不影响其他 rule |
| Aviator 求值超时 (>100ms) | `accrual.status = OPEN_FAILED` + `error_msg` + 不入 invoice |
| 业务事件无匹配 rule | `event_log.process_status = NO_RULE` + 警告日志，不阻塞事件流 |
| rule.expression 引用未注册变量 | 同编译失败处理 |
| invoice 编号生成冲突 | 重试 3 次 + 抛 `FinanceException(INVOICE_NO_CONFLICT)` |
| 重复事件投递 (相同 source_event_id) | 写 event_log 后直接 return（不调 BillingEngine） |
| 重复 accrue (同 tenant+event+biz) | UNIQUE 冲突 → 视为已处理，return existing |
| 跨事务异常 (finalize 时) | 整事务回滚，accrual 保持 OPEN，下次再试 |
