## 0. 背景

骨架已完成（platform-skeleton + iteration 1.5 + IT 硬化 Top 8 三份 plan 全部执行完毕），34 个 IT 通过，Docker 部署验证，前端 8 个页面已可访问。但实际体验暴露几个**生产级缺口**：

| # | 缺口 | 影响 |
|---|---|---|
| 1 | 无 auth guard —— 直接访问 `/users` 等路径不会跳 `/login` | 安全 |
| 2 | access 过期无 silent refresh —— 跑 15 分钟后所有接口 401 | UX |
| 3 | 菜单项对所有登录用户都可见 —— 没有按 perms 过滤 | UX / 安全 |
| 4 | 无 ErrorBoundary —— 渲染崩溃整页白屏 | 健壮性 |
| 5 | 无 404 page —— 任意路径都会进 BasicLayout 渲染空 Outlet | UX |
| 6 | 现有 8 个页面只有"骨架代码"，没有完整 CRUD —— Roles 不能分配权限、Dict 没有子表等 | 业务可用性 |
| 7 | 共享 hooks / 共享 columns 没有抽取 —— 8 个页面重复相似代码 | 可维护性 |
| 8 | 无测试 —— 任何修改靠手测 | CI 阻断 |
| 9 | 无暗黑模式 / i18n | 体验 |

Iteration 2.0 目标：**把 lumen-admin-web 从"能跑"提升到"能进生产"**。

## 2. 架构

### 2.1 Auth / Token 流转

```
                ┌───────────────────────────────────────────────┐
                │   AuthProvider (React Context)                │
                │   - currentUser: {id, username, perms, roles} │
                │   - isAuthenticated: boolean                   │
                │   - login(req) / logout()                     │
                │   - refresh(): silent re-issue access         │
                └───────────────────────────────────────────────┘
                                    ▲
                                    │ useAuth() / useAccess()
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        │                           │                           │
  ProtectedRoute              BasicLayout               pages
  - if no auth                - getCurrentUser().perms    - useAccess()
    → nav('/login')           - 过滤 menuRoute 项           - canRead('user:list')
                                                            - 401 → silent refresh → retry
```

**Token 存储**（不变）：`localStorage.lumen_access` + `localStorage.lumen_refresh`（与现有兼容）。

**Silent refresh 策略**（**新决策**）：
- axios response interceptor 收到 401 → 调 `/auth/refresh`（用 `lumen_refresh`）
- 成功 → 替换 `lumen_access` + `lumen_refresh`，重发原请求
- 失败（refresh 也过期）→ 清两个 token，跳 `/login`（带 `from` 参数回跳）
- 并发去重：同时多个 401 → 只发一次 refresh，其他 await 同一 Promise

### 2.2 菜单权限过滤

```ts
// lumen-admin-web/src/access.ts
export interface Access {
  perms: string[];
  roles: string[];
  canRead: (perm: string) => boolean;
  canAny: (perms: string[]) => boolean;     // 任一满足
  canAll: (perms: string[]) => boolean;     // 全部满足
  hasRole: (role: string) => boolean;
}

// BasicLayout.tsx — 改造 menuRoute 渲染
const menuRoute = {
  path: '/',
  routes: [
    { path: '/users', name: '用户管理', perm: 'user:list' },
    { path: '/roles', name: '角色管理', perm: 'role:list' },
    ...
  ],
};
const access = useAccess();
const visibleRoutes = menuRoute.routes.filter(r => !r.perm || access.canRead(r.perm));
```

### 2.4 ErrorBoundary 设计

```tsx
<ErrorBoundary level="page" onError={(err, info) => log(err, info)}>
  <Users />
</ErrorBoundary>

//   "app"   — 顶层 fallback = "应用崩溃，请刷新"
//   "page"  — 单页 fallback = "本页面加载失败" + Reload 按钮
```

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Silent refresh 并发 100 个请求都触发 → refresh Promise 单例 | Task 4 用闭包缓存 `inflightRefresh: Promise\|null` |
| 菜单过滤把无权限的菜单过滤掉 → 用户不知道有这功能 | BasicLayout 把被过滤掉的项放"隐藏菜单"小角标（v1 暂不做） |
| i18n 自实现 → 维护成本 | 仅 30 个 key，自实现比 react-intl 体积小 30KB |
| 暗黑模式翻车 → Antd v5 token 化好支持 | 用 ConfigProvider theme.token，不写 hardcoded 色值 |
| Vitest + Antd Pro 兼容性问题 | 只测 hooks + 简单 page，不测 ProTable 内部 |
