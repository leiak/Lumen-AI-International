## 0. 背景

平台与跨切面基建（`platform-skeleton`、`iteration-1.5-cross-cutting-foundation`、`iteration-2.0-frontend-deepening`）已全部完成：8 个 maven 模块、13 张 Flyway 迁移、34 个集成测试、前端 9 个 admin 页面 + 主题/i18n/错误边界/401 静默刷新。

**Iteration 3.0 目标**：挑一个对横切能力依赖最强、体量适中、能在前端端到端演示的业务模块（**WMS 仓储**）垂直贯通，作为"业务能力首次落地"。后续 v5/v6 业务模块照此模板复制。

## 1. 范围与不在范围

### 1.1 In Scope（3.0a）

**模块拓扑**：新增 maven module `lumen-wms`，与 `lumen-masterdata` / `lumen-notification` / `lumen-numbering` / `lumen-rbac` 同层。

**实体（12 张表）**
- 主数据 4：`wms_warehouse` / `wms_location` / `wms_item` / `wms_customer`
- 交易 6：`wms_inbound_note` + `wms_inbound_line` / `wms_outbound_note` + `wms_outbound_line` / `wms_inventory_adjust` + `wms_inventory_adjust_line`
- 账本 1：`wms_inventory`（乐观锁）
- 配置 1：`wms_threshold_config`（每租户一份）

**状态机（4 套）**
- `INBOUND` —— `DRAFT → PENDING_APPROVAL? → RECEIVING → PUTAWAY → DONE` / `CANCELLED`
- `OUTBOUND` —— `DRAFT → PENDING_APPROVAL? → PICKING → REVIEW → SHIPPED → DONE` / `CANCELLED`
- `LOCATION` —— `ACTIVE / FROZEN / DISABLED`
- `INVENTORY_ADJUST` —— `DRAFT → PENDING_APPROVAL? → APPROVED → DONE` / `REJECTED` / `CANCELLED`

`PENDING_APPROVAL` 由阈值评估器按租户配置触发。

**接入**：复用 `t_state_transition`（Iter 1.5）、`t_audit`（已有）、`t_event_outbox`（Iter 1.5）、`t_approval_record`（Iter 1.5）、`t_number_rule`（Iter 1.5）、`t_event_outbox`（Iter 1.5）、`TenantContext` 多租户（Iter 1.5）、`@PreAuthorize` RBAC（已有）。

**前端**
- 父菜单 `仓储管理 (/wms/*)` + 9 个子路由
- 复用 Iter 2.0：`useTableRequest` / `useDict` / `<StatusTag>` / `request.ts` 拦截器
- 新增：` <WmsNoteTable>` / `<WmsNoteLinesEditor>` / `<StateTransitionPanel>` / `<ThresholdConfigForm>` + 9 个 service 模块

**测试**
- 后端 service 单测（含阈值分支、乐观锁冲突、库存不足）~20
- 后端 controller 集成 ~15
- 前端 Vitest + RTL `~12 case`
- 累计集成测试目标 **49/49** 通过（已有 34 + 新 15）

**演示**：见 § 7 的 9 步演示路径，含阈值超限触发审批 + 库存不足报错 + 库位冻结拦截。

### 1.2 Out of Scope（推迟到 3.0b / 后续）

- 波次计划（WAVE）
- 补货规则
- 增值服务（拣货费 / 存储费 / 仓租计算）

## 4. 状态机

> 每个状态机都复用 `t_state_transition` + `StateTransitionService`（Iter 1.5 已实现）。本 spec 不修改框架，只在 `t_state_transition` 中 seed 4 套迁移规则。

### 4.1 INBOUND
```
DRAFT ──[submit (阈值不超)]──▶ RECEIVING
DRAFT ──[submit (阈值超)]────▶ PENDING_APPROVAL ──[approve]──▶ RECEIVING
RECEIVING ──[receive (全行收货)]──▶ PUTAWAY
PUTAWAY ──[putaway (全行上架)]──▶ DONE (auto)
* ──[cancel (非 DONE)]──▶ CANCELLED
```

### 4.2 OUTBOUND
```
DRAFT ──[submit (阈值不超)]──▶ PICKING
DRAFT ──[submit (阈值超)]────▶ PENDING_APPROVAL ──[approve]──▶ PICKING
PICKING ──[pick (全行拣完)]──▶ REVIEW
REVIEW ──[review]────────────▶ SHIPPED
SHIPPED ──[done]─────────────▶ DONE (auto)
* ──[cancel (非 DONE)]──▶ CANCELLED
```

### 4.3 LOCATION
```
ACTIVE ──[freeze]──▶ FROZEN
FROZEN ──[activate]──▶ ACTIVE
ACTIVE|FROZEN ──[disable]──▶ DISABLED (终态)
```

### 4.4 INVENTORY_ADJUST
```
DRAFT ──[submit (阈值不超)]──▶ APPROVED
DRAFT ──[submit (阈值超)]────▶ PENDING_APPROVAL ──[approve]──▶ APPROVED / [reject]──▶ REJECTED
APPROVED ──[execute]──▶ DONE
* ──[cancel]──▶ CANCELLED
```

`Disabled Location` 与 `Frozen Location` 都不可作为 `putaway_location_id` / `source_location_id` 使用 —— 由 service 层守卫。

## 6. 关键数据流

### 6.1 入库（阈值不超）
```
1. POST /inbound-notes
   → service 创建 DRAFT, 调 NumberRuleService.generate("INB") 拿 no
   → 返回 {id, no, status: DRAFT}
2. POST /inbound-notes/{id}/lines (×N)
   → 校验 status==DRAFT
   → 插行
3. POST /inbound-notes/{id}/submit
   → ThresholdEvaluator.evaluate(note) → 无审批 → status=RECEIVING
4. POST /inbound-notes/{id}/lines/{lid}/receive {qty: 50}
   → received_qty += 50；若全部 received_qty==qty → status=PUTAWAY
5. POST /inbound-notes/{id}/lines/{lid}/putaway {qty: 50, location_id}
   → UPSERT wms_inventory (qty += 50)；若全部 putaway → status=DONE + completed_at
```

### 6.2 出库（阈值超 → 触发审批）
```
1. POST /outbound-notes                        → DRAFT
2. POST /outbound-notes/{id}/lines × N         → 行 (item, qty, source_location_id)
3. POST /outbound-notes/{id}/submit
   → 计算 (amount = sum(line.qty * item.unit_cost), qty = sum)
   → 校验每行 source_location 状态 (ACTIVE 才可)
   → 读 wms_threshold_config；若 amount > out_amount_threshold || qty > out_qty_threshold
   → 走 reserve: INV.locked_qty += line.qty (乐观锁校验, 失败重试 1 次)
   → 写 t_approval_record(biz_type='WMS_OUTBOUND', biz_id=note.id, status=PENDING)
   → 状态 = PENDING_APPROVAL (reserve 已生效，库存虽被锁但单据待审)
4. POST /outbound-notes/{id}/approve
   → 审批通过 → 状态 = PICKING
   → 库存 reservation 继续生效
5. POST /outbound-notes/{id}/lines/{lid}/pick {qty: 10}
   → 校验 OUT_LINE.line_qty - OUT_LINE.picked_qty >= 10
   → INV.locked_qty -= 10、OUT_LINE.picked_qty += 10
   → 若全行 picked_qty==qty → 状态 = REVIEW
6. POST /outbound-notes/{id}/review            → 状态 = REVIEW (复核，无 INV 变化)
7. POST /outbound-notes/{id}/ship {carrier, tracking_no}
   → 状态 = SHIPPED，写 carrier / tracking_no / shipped_at
8. POST /outbound-notes/{id}/done
   → INV.locked_qty -= line.picked_qty、INV.qty -= line.picked_qty (取每行 picked_qty)
   → 状态 = DONE

注：阈值不超时，submit 直接到 PICKING（仍走 reserve）；reserve 在 submit 中落地，无论是否需要审批。
```

### 6.3 库存调整（报损）
```
1. POST /adjusts → DRAFT
2. POST /adjusts/{id}/lines {item_id, location_id, delta_qty: -5}
3. POST /adjusts/{id}/submit
   → 阈值评估 → 通常不超 → APPROVED
4. POST /adjusts/{id}/execute
   → UPSERT wms_inventory SET qty = qty + delta_qty (校验 >=0)
   → 状态 = DONE
```

## 7. 错误处理

| 失败场景 | 异常类 | HTTP |
|---|---|---|
| 状态机非法迁移 | `IllegalStateTransitionException(from, to)` | 409 |
| 库存不足 (qty < required) | `InventoryInsufficientException(available, required)` | 409 |
| 库位 ACTIVE/FROZEN 不可用 | `LocationNotAvailableException(id)` | 409 |
| 乐观锁冲突 | `OptimisticLockingFailureException` → 全局包装为 `ConcurrentModifiedException` | 409 |
| 租户越权 | `TenantMismatchException` | 403 |
| 业务校验失败 (DRAFT 后不可改 / 行在错误状态) | `IllegalNoteStateException` | 422 |
| 审批已 CLOSED | `ApprovalClosedException` | 409 |
| 负库存违反 CHECK | `InventoryNegativeException` | 500 (兜底, 正常流不该发生) |

全局异常处理沿用 `lumen-extension` 的 `GlobalExceptionHandler`，按 `BizCodeEnum` 翻成 `Result<T>`。前端 `request.ts` 拦截器按 `bizCode` 分类 toast。

### 7.1 并发控制

- 所有 `wms_inventory` 读写都 `@Version`
- 出库 `pick` / `done` 使用 `@Transactional` + `OptimisticLockingFailureException` 捕获 → 重试 1 次
- 入库 `putaway` 与出库 `pick` 都期望 INV 行已存在；UPSERT 走 DB 唯一键 (tenant_id, warehouse_id, location_id, item_id) 不重复

### 7.2 审计 + 事件

- 11 张表全部走 `@AuditField` 自动写 created_*/updated_*
- 状态机迁移每个动作发 `outbox_event` (lumen-extension 已有)：`event_type='WMS_INBOUND_STATE_CHANGED'` 等，含 from/to/operator
- 阈值评估通过的写 `t_event_outbox('WMS_THRESHOLD_EVALUATED', ...)` 仅日志用，不影响流程

## 8. 阈值审批集成

### 8.1 ThresholdEvaluator

```java
@Component
public class ThresholdEvaluator {
  public boolean requiresApproval(NoteKind kind, BigDecimal amount, BigDecimal totalQty, Long tenantId) {
    WmsThresholdConfig cfg = configService.getOrDefault(tenantId);
    if (!cfg.isEnabled()) return false;
    BigDecimal amtThr = thresholdOf(kind, "amount", cfg);
    BigDecimal qtyThr = thresholdOf(kind, "qty", cfg);
    boolean amtExceed = amtThr.signum() > 0 && amount.compareTo(amtThr) > 0;
    boolean qtyExceed = qtyThr.signum() > 0 && totalQty.compareTo(qtyThr) > 0;
    return cfg.isApprovalRequiredWhenExceed() && (amtExceed || qtyExceed);
  }
}
```

### 8.2 触发链

```
submit(note)
  ├─→ ThresholdEvaluator#requiresApproval(kind, amount, totalQty, tenantId)
  │     ├─ false → 状态机直接到 RECEIVING / PICKING / APPROVED
  │     └─ true  → ApprovalService.create(biz_type, biz_id, ...)
  │                 → 状态机到 PENDING_APPROVAL
  └─→ StatusMachine.transit(note, NEXT_STATUS)

approve(note)
  └─→ ApprovalService.approve(biz_type, biz_id)
  └─→ StatusMachine.transit(note, NEXT_STATUS_AFTER_APPROVAL)
```

> 注：`ApprovalService` 是 Iter 1.5 实现的通用审批门面，本 spec 不引入新的审批维度，复用现有 `t_approval_record` + 现有的 `APPROVAL_LIST/APPROVE` 权限点（V13 已 seed）。

## 13. 演示路径（验收用例）

启动后用 `admin / admin123` 登录（默认租户 1）：

1. **录入主数据**：
   - 新建仓库 `WH-A`（type=SELF, address=上海闵行）
   - 新建库位 `A-01` / `A-02` / `B-01` / `B-02`（自动 ACTIVE）
   - 新建货品 `SKU-001~010`，引用 `sys_uom=PCS`
   - 新建客户 `CUST-A` / `CUST-B`

2. **配置阈值**：进 `/wms/settings/threshold`，把 `out_amount_threshold=1000`、`adj_amount_threshold=0`、`enabled=true`

3. **入库小单**：`WH-A` 收 `SKU-001 × 100件` 给 `CUST-A`
   - 提交（无审批，因为默认 0/0）→ RECEIVING
   - 收货 → PUTAWAY
   - 上架到 `A-01` → DONE

4. **库存查询**：`/wms/inventory` 过滤 `WH-A` → `A-01 / SKU-001 = 100 件`

5. **出库小单**：`WH-A` 出 `SKU-001 × 10件` 给 `CUST-A`
   - 提交（阈值不超，单价 1 元 × 10 = 10 < 1000）→ PICKING
   - 拣货 10 → REVIEW
   - 复核 → SHIPPED（填 carrier / tracking_no）
   - done

6. **库存查询**：`A-01 / SKU-001 = 90`

7. **出库大单**：`SKU-001 × 80件` 给 `CUST-B`
   - 提交（80 > 0 但 amt = 80 < 1000，阈值仍不超 → 但为演示可改阈值为 `out_qty_threshold=50`）
   - 演示阈值超限 → 进 `PENDING_APPROVAL` → 切到 `admin2` 账号 → approve → 走完 pick/review/ship/done

8. **调整单**：`WH-A/A-01/SKU-001` 报损 `-5`
   - 建单 → submit → APPROVED → execute → 库存 = 85

9. **库位冻结**：把 `A-01` 冻结（`FROZEN`）
   - 再走一次入库 putaway → `LocationNotAvailableException`（演示失败路径）
