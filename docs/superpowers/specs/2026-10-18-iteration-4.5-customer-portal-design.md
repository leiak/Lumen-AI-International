# Iteration 4.5 — 客户门户 (B2B Self-Service) 主设计

> **For agentic workers:** 继承 4.1.x / 4.2 / 4.3.1 / 4.3.2 / 4.4 (V25..V32, wms / dispatch / cs / finance 完整闭环, 26+ entities, 18 services, 110+ 单元, 30+ IT, 300+ Vitest, 50+ endpoints). 4.5 把这些能力暴露给客户 (B2B 商家) 自助使用 — 不再全部走 CS 坐席.

**Goal:** 商家 (B2B 客户) 通过独立 SPA `lumen-customer-web` 自助完成"查货 / 下单 / 对账 / 评价"四大场景, 替代 80% 走 CS 坐席的查询/操作类工单. 本 spec 定义 4.5 整体架构 + 4.5A 第一个 sub-iteration 的具体交付, 4.5B/4.5C/4.5D 由各自 spec 接力 (后续 sprint 单独 brainstorm).

**Architecture:** 客户身份复用 `sys_user` + `customer` 角色 + 新 `t_customer_user_link` (用户 ↔ wms_customer 多对多, 一会话一 active). 后端薄门面 `lumen-customer` 模块: 控制器 / DTO / 权限校验, 业务调用下沉到 `lumen-dispatch` / `lumen-finance` / `lumen-wms` 既有 service (加 customerId 范围过滤). 前端独立 Vite SPA `lumen-customer-web` (独立端口 5174, 独立 JWT `aud=portal`, 独立 deploy). 数据范围: 登录后从 link 表取 active customer_id, 强制 `WHERE customer_id = ?` 注入所有查询.

**Tech Stack:** Spring Boot 3.2.5 + MyBatis-Plus 3.5.7 + Flyway 9.x + JJWT 0.11 (在 lumen-common/security/JwtUtil 增 `aud` claim) + Lombok + JUnit 5 + Testcontainers. Vite 5 + React 18 + TS 5 + Antd 5 + ProComponents 2.7 + Vitest 1 + RTL + MSW 2. (与既有栈完全一致, 不引入新依赖.)

## 1. 背景与目标

### 1.1 现状 (4.4 末态)

- 后端 8 模块: `lumen-rbac` / `lumen-masterdata` / `lumen-numbering` / `lumen-wms` / `lumen-dispatch` / `lumen-cs` / `lumen-finance` / `lumen-notification` / `lumen-extension`
- 员工 SPA `lumen-admin-web` (Vite 5173, 30+ 页面) — 全部是后台角色 (admin / 运营 / 财务 / 客服)
- 客户 (`wms_customer` 表, 含 code/name/contact/phone/address) **没有登录入口**, 全部交互走:
  - CS 坐席接电话查运单 / 下单 / 改单
  - 财务发邮件发对账单
  - 客服代客提交工单
- 商家主动行为 (查货 / 看账单 / 评价) 几乎没有自助通道

### 1.2 缺口 (驱动 4.5)

1. **没有客户登录** — 商家收不到运单状态主动推送, 只能打 CS 电话
2. **没有自助下单** — 商家要下单得通过 CS 录入, CS 人员 60% 时间花在录入
3. **没有自助对账** — 财务发 PDF/Excel 给商家, 商家核对后再发邮件反馈差异
4. **没有评价通道** — 配送质量反馈只能打 12345 / 投诉信
5. **没有数据隔离边界** — 客户操作类需求如果开放, 必须严格"客户 A 看不到客户 B"

### 1.3 目标 (4.5)

| 目标 | 验收 | 优先级 | sub-iter |
|------|------|--------|----------|
| 客户身份 | `sys_user` + `customer` 角色 + `t_customer_user_link` 多对多 + 一会话一 active customer | P0 | 4.5A |
| 客户登录 | 独立 `/auth/portal/login` + JWT `aud=portal` + 刷新 token 流 (复用 lumen-rbac 既有) | P0 | 4.5A |
| 客户门户 SPA | `lumen-customer-web` 独立 Vite 工程, 端口 5174, 独立 i18n + 独立菜单 | P0 | 4.5A |
| 查货 (Track) | 列表 / 详情 / 轨迹时间线 / POD 图片预览, 接 dispatch 既有 DO 状态机只读 | P0 | 4.5A |
| 4.5A 数据隔离 | 任何 portal 端点强制 `WHERE customer_id = ?` (从 active customer 注入) | P0 | 4.5A |
| 4.5A 文档 | README §15.13 增量 | P0 | 4.5A |
| 下单 (Order) | 商家下单 / 取件预约 / 价格预估, 接 dispatch 状态机 + billing 规则 | P1 | 4.5B (后续) |
| 对账 (Recon) | 商家看对账单 / 发票 / 付款, 接 V31/V32 reconciliation + invoice + payment_record | P1 | 4.5C (后续) |
| 评价 (Rating) | 运单完成后商家评分 + 评论, 接 CS escalation | P2 | 4.5D (后续) |
| 工单 (Ticket) | 商家直接提工单, 接 CS ticket | P2 | 4.5D (后续) |

### 1.4 非目标 (YAGNI 4.5 排除)

- ❌ 终端消费者 (B2C) 门户 — 这是 B2B 商家侧, C 端寄件人 4.5 暂不碰
- ❌ 微信小程序 / 钉钉 / 飞书集成 — 4.5 只做 Web SPA
- ❌ 移动 App / RN / Flutter — 同上
- ❌ SSO / OAuth 2.0 第三方登录 — 一期只做账号密码
- ❌ 双因素认证 (2FA / TOTP) — 留口子 (sys_user.password_hash 旁预留 mfa_secret), 一期不接
- ❌ 商家自助注册 / 实名认证 — 商家由内部销售开通, 不接受公网注册
- ❌ 商家支付 (在线付款 / 退款) — 4.5C 只看对账单, 付款走银行流水由财务录入
- ❌ 价格自动议价 / 合同价 — 4.5B 价格预估走既有 billing rule, 不做谈判
- ❌ 客户间消息 (商家-商家) — 4.5 不做
- ❌ 数据导出权限 (限单条/批量/字段级) — 4.5A 简单"已登录就能看自己", 字段级权限 4.5C 再加

### 2.1 依赖关系

- `lumen-customer` 依赖 `lumen-dispatch` / `lumen-finance` / `lumen-wms` / `lumen-rbac` / `lumen-masterdata` / `lumen-common`
- `lumen-customer` 不依赖 `lumen-cs` / `lumen-notification` (4.5A 不接, 4.5D 接 CS)
- `lumen-customer-web` 独立前端工程, 不与 `lumen-admin-web` 共享代码 (除 types/api 协议文档)
- `lumen-bootstrap` 加 V33 migration + 在 `application.yml` 配 `lumen.security.jwt.audience=portal|admin` (按 profile 区分)

### 2.2 与既有 4.x 的关系

- 4.5A 在 4.4 末态上**纯增量**: 不动既有 entities / service / 既有 IT
- 既有 lumen-rbac 的 `/api/auth/login` 走 `aud=admin`; 新加 `/api/auth/portal/login` 走 `aud=portal`
- 既有 `lumen-common/security/JwtUtil` 增 `audience` claim, 既有 token 自动带 `aud=admin` (向后兼容)
- 既有 `JwtAuthenticationFilter` 增 audience 校验, 默认要求 `aud=admin`; portal 端点通过 `@PreAuthorize` + 自定义 `aud=portal` 要求解耦 (用 request matcher 而不是改 filter)

### 3.2 登录流 (4.5A)

```
1. POST /api/auth/portal/login
   { username, password }
   ↓
2. AuthService.portalLogin():
   - 校验 sys_user (username + bcrypt password)
   - 校验 sys_user 绑定的 sys_role 至少有一个是 'customer' (id 14)
   - 从 t_customer_user_link 查 user 的所有 customer_id 列表
   - 若 0 个 → 401 "该账号未开通客户门户"
   - 若 1 个 → active_customer_id = 该值 (自动登录到该 customer)
   - 若 N 个 → 返回响应 { mfaChoiceRequired: true, choices: [{id, code, name}, ...] } (不返回 token)
   ↓
3a. (单 customer) 直接签 JWT
    {
      sub: user_id,
      aud: "portal",
      tenant_id,
      active_customer_id,
      roles: ["customer"],
      perms: ["customer:track:view", ...],
      iat, exp
    }
3b. (多 customer) 客户端收到 mfaChoiceRequired 列表, 渲染"选择客户"页
    POST /api/auth/portal/select-customer { customer_id }
    → 校验 user 确实绑了该 customer → 签 JWT 同 3a
   ↓
4. 客户端 (lumen-customer-web) 存 access_token (内存) + refresh_token (httpOnly cookie)
   axios 拦截器: 每个请求 Authorization: Bearer <token>
   401 → 自动 /api/auth/portal/refresh
```

### 3.3 JWT audience 校验

```java
// lumen-rbac/security/JwtAuthenticationFilter.java (扩展, 不破既有)
public class JwtAuthenticationFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(...) {
        String token = extractToken(request);
        if (token == null) { chain.doFilter(...); return; }
        Claims claims = jwtUtil.parse(token);
        String aud = claims.getAudience(); // 既有 JwtUtil 加 getAudience()
        String path = request.getRequestURI();

        // audience 路由
        if (path.startsWith("/api/auth/portal") || path.startsWith("/api/customer/")) {
            if (!"portal".equals(aud)) throw new AuthException(401_001, "需要 portal token");
        } else if (path.startsWith("/api/")) {
            if (!"admin".equals(aud)) throw new AuthException(401_001, "需要 admin token");
        }
        // 通过 → 既有逻辑设置 SecurityContext
    }
}
```

`lumen-common/security/JwtUtil` 在签发时**默认写 `aud=admin`** (既有行为不变), `AuthService.portalLogin` 显式写 `aud=portal`.

### 4.2 拦截器

```java
// lumen-customer/security/CustomerContextFilter.java (新)
@Component
@Order(Ordered.HIGHEST_PRECEDENCE + 100)
public class CustomerContextFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(...) {
        try {
            if (request.getRequestURI().startsWith("/api/customer/")) {
                Long userId = SecurityContextHolder.getContext().getAuthentication().getUserId();
                Long customerId = jwtUtil.getActiveCustomerId(token); // 从 JWT 直接取
                CustomerContext.set(userId, customerId);
            }
            chain.doFilter(...);
        } finally {
            CustomerContext.clear();
        }
    }
}
```

### 4.3 service 层强制范围

每个 portal 调用的 service 方法 (既有 dispatch / finance / wms 的 service 增一个 `customerId` 形参, 不传则不限制, 传则注入 `WHERE customer_id = ?`). 4.5A 范围内:

- `DeliveryOrderService.pageForCustomer(tenantId, customerId, query)` — 既有 `page(tenantId, query)` 加一个重载, **不**改原方法 (staff 调用照常不受限)
- `DeliveryOrderService.getDetailForCustomer(tenantId, customerId, doId)` — 校验 ownership, 不是该 customer 的 DO 抛 404_005
- 类似 `PaymentRecordService` / `ReconciliationService` / `InvoiceService` 各加重载

> **关键: 不动既有 staff service 行为, 只加重载.** staff 调用走原方法, portal 调用走新重载, 编译期就分流.

### 4.4 audit log 加 audience

`AuditLogAspect` (lumen-common/audit) 增字段 `audience` (`admin` | `portal` | `system`), 由 `CustomerContext` 决定填啥. 这样日志能区分"这是哪个 audience 触发的" — 排查客户侧问题直接 grep `audience=portal`.

### 5.3 与既有 dispatch 的对接

4.5A 在 `lumen-dispatch` 加 3 个新方法 (不改既有):

```java
// lumen-dispatch/service/DeliveryOrderService.java (既有, 加重载)
public IPage<DeliveryOrder> pageForCustomer(Long tenantId, Long customerId, TrackQuery q) {
    // 内部用 LambdaQueryWrapper 强加 .eq(DeliveryOrder::getCustomerId, customerId)
}

public DeliveryOrder getDetailForCustomer(Long tenantId, Long customerId, Long doId) {
    DeliveryOrder d = get(tenantId, doId);
    if (!customerId.equals(d.getCustomerId())) {
        throw new DispatchException(NOT_FOUND, 404_005);
    }
    return d;
}

public Pod getPodForCustomer(Long tenantId, Long customerId, Long doId) {
    getDetailForCustomer(tenantId, customerId, doId); // 抛 404 if not own
    return podService.getByDoId(doId);
}
```

`TrackQuery` 字段: `doNo` (like), `status` (in), `dateFrom`, `dateTo`, `page`, `size`. 排序: `created_at desc`. 字段白名单: 业务字段 + status, **不返** `tenant_id` / `created_by` / `updated_by` (这些是 staff 侧用, 客户不需要看到).

### 5.4 不在 4.5A 范围 (YAGNI)

- ❌ portal 端调既有 `/api/finance/invoice` (走 staff RBAC) — 4.5C 在 `lumen-customer` 加独立 `PortalInvoiceController`, **不**复用 staff controller
- ❌ portal 端调既有 `/api/dispatch/order` (下单) — 4.5B 在 `lumen-customer` 加 `PortalOrderController`
- ❌ portal 端调既有 `/api/cs/ticket` — 4.5D 加 `PortalTicketController`
- ❌ portal 端调既有 `/api/finance/reports` — 4.5C 加 `PortalReportController`
- 原因: staff controller 的 RBAC 是 `finance:*:l1_approve` 之类的细粒度, customer 角色绑的是 `customer:*:view`, 走 staff controller 必 403. 强行复用会引入复杂 audience 切换. 新 controller 直白.

## 8. 跨切关注

### 8.1 i18n

- 客户门户文案与 staff 文案**解耦** (不放 lumen-admin-web 的 locale). 商家侧用词更口语化 ("您的运单" vs "运单管理").
- 默认 zh-CN, en-US 留空架 (4.5A 范围).

### 8.2 错误码

- 新错误码空间 `4xx_customer_xxx` / `5xx_customer_xxx`, 与 staff 的 `4xx_finance_xxx` 等并列.
- 401_001: 需要 portal token (在 admin 端点用了 admin token)
- 401_002: 未激活客户身份 (Token 没 active_customer_id)
- 403_001: 无权访问该 customer (用户没绑该 customer)
- 404_005: 资源不存在或无权 (复用 dispatch 的, 不暴露"是别人的"细节)

### 8.3 audit

- `AuditLogAspect` 加 `audience` 字段 (`admin` | `portal` | `system`).
- portal 端所有 mutating 操作 (`PUT /api/customer/profile`) 都进 audit, 字段 `customer_id` 由 `CustomerContext` 注入.
- 既有 staff 操作 log 不受影响.

### 8.4 限流 (rate limit)

- 4.5A **不**做. 流量预计低 (商家每日 10-50 次访问). 4.5B 下单再做 (防脚本).

### 8.5 监控

- 4.5A **不**做. 接既有的 Spring Boot Actuator 即可. 4.5C 加 Micrometer 计数 (portal 端 QPS / 失败率).

### 8.6 安全

- bcrypt 密码复用既有 (`sys_user.password_hash` 已有)
- 登录失败计数 (5 次锁 10 分钟) — 4.5A 暂不做, 4.5B 复用 staff 既有的 (在 `AuthService.login` 加)
- 验证码 (图形 / 短信) — 4.5A 不做
- session 时长 — access_token 2h, refresh_token 14d, 与 staff 既有对齐

## 11. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| portal token 被 staff 端点误接受 | 中 | 高 (越权) | audience 路由校验 + IT 强制覆盖 (PortalAuthIT #5) |
| 客户 A 看到客户 B 的 DO | 中 | 极高 (合规) | 强制 `WHERE customer_id = ?` + 4.5A 范围 4 个 IT 覆盖 (PortalTrackIT #2/3/4) |
| 新 lumen-customer 模块在 deploy 后忘了配 nginx 5174 → 8080 proxy | 低 | 中 | deploy runbook + README §15.13 必含 nginx 片段 |
| 商家第一次登录体验差 (不知用户名/密码) | 中 | 中 | 4.5A 在 admin 端 (CS 坐席侧) 加一个"打印客户登录指引"按钮, 邮件模板套用既有 lumen-notification |
| 多客户切换泄露 (切到客户 A 后没刷, 看到 A 的数据) | 中 | 中 | store 切客户时强制 `window.location.reload()`, 避免 React state 残留 |
| 4.5A 推完后 lumen-admin-web 与 lumen-customer-web 双 deploy pipeline 还没建 | 高 | 中 | 4.5A push 前给运维提单 (Jira), 至少 dev 环境有 manual deploy 文档 |
| JwtUtil 加 audience 破既有 staff token | 低 | 高 | audience 默认 `admin` + 既有签发 token 仍有效 (解析时 .getAudience() 返 null 不阻断), 1 个单元覆盖 |
