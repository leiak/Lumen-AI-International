# 基础资料业务细化 v3.0

> 基础资料（Master Data）是整个国际物流系统的"地基"，决定了业务单据能否被准确创建、引用与流转。
> 本文档对客户、合作方、港口、航线、HS编码、仓库、币种、国家、柜型等主数据进行**业务级**深化设计。

---

## 〇、文档约定

每个主数据模块按以下结构细化：

1. **业务边界**（明确归属）
2. **核心实体详解**（字段、枚举、约束）
3. **业务规则**（唯一性、联动、校验）
4. **状态机**
5. **业务流程**（新增/变更/停用）
6. **与其他模块的交互**
7. **可配置项**
8. **异常与边界场景**
9. **报表与分析维度**

## 一、业务边界与主数据治理原则

### 1.1 什么是主数据

| 主数据类别 | 定义 | 业务影响范围 |
| --- | --- | --- |
| 客户档案 | 委托我方操作的发货人、收货人、贸易公司 | 报价、订单、结算 |
| 合作方档案 | 船公司、航司、铁路、拖车、报关行、仓库、代理 | 订舱、操作、财务 |
| 港口/航线 | 起运港、目的港、中转港、航线定义 | 报价、订舱、跟踪 |
| HS编码 | 海关商品分类编码 | 报关、关税、监管 |
| 仓库 | 集货仓、保税仓、海外仓 | 仓储作业 |
| 币种 | 交易与结算货币 | 报价、结算、报表 |
| 国家/地区 | 起运国、目的国、原产国 | 报关、统计 |
| 柜型 | 集装箱规格 | 报价、订舱、装箱 |

### 1.2 主数据 vs 业务数据 vs 交易数据

| 数据类型 | 特点 | 示例 | 更新频率 |
| --- | --- | --- | --- |
| 主数据 | 全局共享、相对稳定、有治理流程 | 客户档案、船公司档案 | 低频 |
| 业务数据 | 与主数据关联、半结构化 | 协议价、模板 | 中频 |
| 交易数据 | 业务过程中产生、不可变 | 订单、提单、账单 | 高频 |

### 1.3 主数据治理原则

- **唯一性**：每类主数据有唯一业务编码（人读 + 系统码）
- **完整性**：必填字段必须填全才能启用
- **一致性**：跨模块引用同一主数据（如客户的币种、账期、地址全局一致）
- **可追溯**：所有变更留痕（操作人、时间、前后值）
- **可审核**：重要主数据需审核生效（如新增大客户、合作方启用）
- **可停用**：停用不影响历史数据，仅控制新业务引用
- **分级管控**：核心字段（账号、税号）受权限保护

## 二、客户主数据（Customer Master Data）

### 2.1 业务边界

**属于客户主数据：**
- 公司信息（名称、税号、地址）
- 业务属性（客户类型、分级、来源）
- 财务属性（授信、账期、结算币种）
- 关务属性（AEO、EORI、美国税号）
- 联系人、客户地址

**不属于客户主数据：**
- 客户订单（业务数据）
- 客户报价历史（业务数据）
- 客户对账单（业务数据）

### 2.2 客户类型详解

| 客户类型 | 业务特征 | 默认账期 | 默认信用额度 | 备注 |
| --- | --- | --- | --- | --- |
| 货主（Direct Shipper） | 工厂/贸易商直接委托 | 月结30天 | 50万 | 主战场 |
| 同行（Forwarder Peer） | 货代同行委托操作 | 月结15天 | 30万 | 利润率低 |
| 代理（Agent） | 中间商、二级代理 | 预付 | 10万 | 严控信用 |
| 跨境电商（CBE Seller） | 跨境平台卖家 | 月结15天 | 20万 | 小批量高频 |
| 工厂（Manufacturer） | 自有出口业务 | 月结60天 | 100万 | 长期合作 |
| 个人（Individual） | 散客 | 全额预付 | 0 | 限定服务 |

### 2.3 客户分级的判定规则

| 等级 | 判定标准（满足任一） | 优惠策略 |
| --- | --- | --- |
| VIP | 近12个月货量≥100 TEU 或 收入≥500万 | 一口价、最优服务 |
| A | 近12个月货量≥50 TEU 或 收入≥200万 | 协议价、专属客服 |
| B | 近12个月货量≥10 TEU 或 收入≥50万 | 标准报价 |
| C | 近12个月货量<10 TEU | 市场报价 |
| 潜在 | 仅询价无订单 | 无优惠 |

> **业务规则**：客户分级每月1日凌晨自动重算；销售可手动调整，但需主管审批。

#### 2.6.2 地址字段规则

- **唯一性**：同一客户同一类型地址名称不可重名
- **默认值**：每个客户每个地址类型最多1个默认地址
- **地理坐标**：建议维护（用于拖车调度、地图展示）
- **区域识别**：必须落到省市区（中国客户）

### 2.7 客户生命周期与状态机

```
潜在客户 ─→ 新建待审 ─→ 审核通过 ─→ 正常 ─→ 冻结 ─→ 失效
                ↓             ↓          ↓
              审核驳回      启用中      黑名单
                  ↓                    ↓
                废弃                  永久冻结
```

| 状态 | 含义 | 可建业务单 | 可查询 | 解除条件 |
| --- | --- | --- | --- | --- |
| 待审 | 提交未审核 | ❌ | ✅ | 审核通过/驳回 |
| 正常 | 启用 | ✅ | ✅ | - |
| 冻结 | 暂停业务 | ❌（已有单据可继续） | ✅ | 解除冻结 |
| 黑名单 | 永久拒绝 | ❌ | ✅ | 不可解除 |
| 失效 | 长期未合作 | ❌ | ✅ | 重新启用 |
| 废弃 | 审核未通过 | ❌ | ❌ | 不可恢复 |

### 2.8 客户业务规则

#### 2.8.1 唯一性约束

- 公司名称 + 国家：唯一（避免重名）
- 税号 + 国家：唯一（同一税号不可重复建档）
- 客户编码：全局唯一

#### 2.8.2 信用控制

```
可用信用 = 授信额度 - 当前未收应收 + 已开票未收
当客户新建委托单 → 校验可用信用 ≥ 该单预估金额
否则：提示超信用 → 销售经理审批 → 通过则下单，否则拒绝
```

#### 2.8.3 自动编号规则

```
客户编码 = 前缀(CUS) + 年份(4位) + 月份(2位) + 流水号(4位)
示例：CUS2026090001
```

### 2.9 客户业务流程

#### 2.9.1 新增流程

```
销售提交客户信息 → 客服/主管审核（资质、证件）→ 审核通过 → 客户生效
                                                  ↓
                                              审核驳回 → 通知销售补充/废弃
```

#### 2.9.2 变更流程

```
销售/客服提交变更申请 → 审核（财务/主管） → 生效 → 通知客户
变更类型：
  - 基础信息变更：仅需主管审核
  - 财务属性变更（账期、授信）：需财务主管审核
  - 关务属性变更：需关务审核
  - 停用/冻结：需主管审批
```

### 3.7 合作方档案字段通用规则

#### 必填字段

- partner_code（系统生成）
- partner_type（分类）
- partner_name_cn（中文名）
- partner_name_en（英文名）
- country_code（所在国家）
- enable_flag（启用）

#### 业务规则

- **唯一性**：partner_code 全局唯一；同一类型下 partner_name + country 唯一
- **结算币种**：必须填，影响后续应付账单币种
- **银行信息**：用于付款，需校验账号格式
- **联系人**：每个合作方至少 1 个业务联系人 + 1 个财务联系人

### 3.8 合作方协议与价格

### 3.9 合作方绩效评估

| 维度 | 指标 | 计算口径 |
| --- | --- | --- |
| 准点率 | 准时订舱/派车/派送占比 | 实际时间 vs 承诺时间 |
| 差错率 | 单证/操作差错占比 | 差错次数 / 总单数 |
| 响应速度 | 平均响应时长 | 申请到反馈时长 |
| 账期遵守 | 按期付款率 | 准时付款金额 / 应付款金额 |
| 客户满意度 | 客户评价分 | 1-5 星 |

> 评分每月自动计算；得分低于阈值触发预警。

### 3.10 合作方状态机

```
潜在 ─→ 接洽中 ─→ 资质审核 ─→ 试合作 ─→ 正式启用 ─→ 长期合作 ─→ 退出
                                                              ↓
                                                          冻结/黑名单
```

| 状态 | 含义 | 可发单 | 解除条件 |
| --- | --- | --- | --- |
| 潜在 | 初步接触 | ❌ | 进入接洽 |
| 接洽中 | 商务洽谈 | ❌ | 完成审核 |
| 资质审核 | 资料审核中 | ❌ | 审核通过 |
| 试合作 | 试单阶段 | ✅（限频次） | 转正式/退出 |
| 正式启用 | 长期合作 | ✅ | - |
| 长期合作 | 战略级 | ✅ | - |
| 冻结 | 暂停 | ❌ | 解除冻结 |
| 黑名单 | 永久拒绝 | ❌ | 不可解除 |
| 退出 | 终止合作 | ❌ | 不可恢复 |

### 3.11 合作方业务流程

#### 3.11.1 新增流程

```
商务接洽 → 收集资质 → 主管审核 → 录入系统 → 试合作（3-5单）→ 正式启用
                ↓
              资质不全 → 拒绝
```

#### 3.11.2 资质管理

## 五、HS 编码主数据（HS Code）

### 5.1 业务定位

HS 编码是海关商品分类编码，用于：
- 报关申报（必填）
- 关税计算
- 监管证件判定
- 禁限运检查

### 5.2 HS 编码结构（10 位）

| 层级 | 位数 | 含义 | 维护主体 |
| --- | --- | --- | --- |
| 章 | 2 位 | 章节（如 85 = 电气设备） | 国际 |
| 类 | 4 位 | 类（如 8517 = 电话） | 国际 |
| 项 | 6 位 | 项（如 851712 = 智能手机） | 国际 |
| 子项 | 8 位 | 子项 | 中国海关 |
| 附加 | 10 位 | 附加 | 中国海关 |

### 5.3 HS 编码字段详解

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| hs_code | ✅ | 10 位编码 |
| description_cn | ✅ | 中文品名 |
| description_en | ✅ | 英文品名 |
| unit | ✅ | 法定计量单位 |
| import_tax_rate | ✅ | 最惠国税率 / 普通税率 |
| export_tax_rate | ✅ | 出口税率（0/有） |
| vat_rate | ✅ | 增值税率（13%/9%） |
| consumption_tax | ⚪ | 消费税 |
| regulation_doc | ✅ | 监管证件（如 A/B 证） |
| inspection_required | ✅ | 是否法定商检 |
| is_dangerous | ✅ | 是否危险品 |
| ciq_code | ⚪ | CIQ 编码（出入境检验检疫） |
| valid_from / valid_to | ✅ | 海关税率生效日期 |

### 5.4 HS 编码预归类服务（增值）

- 客户上传产品图/规格 → 系统推荐 HS 编码 → 关务审核 → 客户采纳
- 历史归类记录可复用

### 5.5 HS 编码更新机制

- **年度调整**：每年 1 月 1 日中国海关调整
- **税率调整**：不定期
- **更新方式**：
  - 海关数据导入（自动）
  - 手工维护（关务专员）
- **更新影响**：存量报关单使用原 HS 编码，不追溯

### 5.6 HS 编码与其他模块的交互

- 询价 → 货物明细 HS 编码（辅助关务）
- 委托单 → 货物明细 HS 编码（必填，影响报关）
- 报关单 → 报关项号 HS 编码（必填）
- 报关明细 → HS 编码 + 税率 + 监管证件

### 5.7 HS 编码异常场景

| 场景 | 处理 |
| --- | --- |
| 客户 HS 编码错误 | 关务审核驳回，要求修改 |
| HS 编码税率变更 | 系统预警，提示已存在报关单 |
| 客户 HS 编码与品名不符 | 关务预归类修正 |
| 监管证件缺失 | 阻止报关申报 |

## 十、主数据治理流程（通用）

### 10.1 新增流程（以客户为例）

```
申请（销售） → 录入 → 主管审核 → 关务/财务复核（如需）→ 启用
                                                       ↓
                                                  通知申请人
```

### 10.2 变更流程

```
变更申请 → 类型判定
            ├── 基础信息 → 主管审核 → 生效
            ├── 财务属性 → 财务审核 → 主管审核 → 生效
            ├── 关务属性 → 关务审核 → 生效
            └── 状态变更（冻结/失效）→ 主管审批 → 生效
```

### 10.3 停用流程

```
申请 → 主管审批 → 财务确认无欠款 → 关务确认无在途 → 停用 → 归档
```

### 10.4 数据质量校验

- 必填字段检查
- 唯一性检查（编码、税号、名称+国家）
- 引用一致性（停用的合作方不可新发单）
- 完整性（启用前必填字段必须完整）

| 场景 | 处理 |
| --- | --- |
| 港口代码冲突 | 优先使用 UN/LOCODE |
| 港口临时关闭 | 标记不可用 + 推荐替代港 |
| 航线调整 | 班期变更需通知客户 |

### 14.4 HS 编码异常

| 场景 | 处理 |
| --- | --- |
| 客户误填 HS 编码 | 关务驳回，要求修正 |
| HS 编码税率变更 | 自动预警 |
| 监管证件缺失 | 阻止报关申报 |
| 危险品 HS 编码 | 自动触发危险品特殊流程 |

### 14.5 仓库异常

| 场景 | 处理 |
| --- | --- |
| 仓库容量不足 | 系统预警，禁止新预约 |
| 仓库温控异常 | 触发冷藏货物异常工单 |
| 仓库关停 | 在途单据紧急转出 |

```
┌─────────────────────────────────────────────────────────────┐
```

## 十七、小结

基础资料业务细化的核心要点：

1. **以客户和合作方为两大核心**，围绕这两个主数据构建业务关系
2. **港口、航线、HS编码、仓库**作为业务必需的主数据，必须先建立
3. **币种与汇率**贯穿所有业务模块，必须严格管理
4. **主数据治理**是体系化工作：唯一性、完整性、可追溯、可审核
5. **可配置化**：客户分级阈值、合作方绩效阈值、编码规则均可配置
6. **异常处理**：预案完善，避免影响业务运行
