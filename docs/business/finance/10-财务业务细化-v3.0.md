## 一、业务边界与范围

### 1.1 财务的业务定位

```
业务单（订单/订舱/报关/仓储）→ 应收账单 ─→ 收款 ─→ 核销
                                              ↓
业务单 → 应付账单 ─→ 付款 ─→ 核销
                                       ↓
                                  对账单 ─→ 客户/供应商确认
                                       ↓
                                  利润分析 / 财务月结
```

| 模块 | 业务范围 |
| --- | --- |
| 应收（AR） | 客户账单生成、对账、收款 |
| 应付（AP） | 供应商账单生成、对账、付款 |
| 收付款 | 银行收款、付款 |
| 对账 | 客户/供应商对账 |
| 计费引擎 | 自动生成账单 |
| 多币种与汇率 | 汇率管理与折算 |
| 利润分析 | 订单/客户/航线利润 |

### 1.2 业务范围

**属于本模块：**
- 应收账单生成、对账、收款核销
- 应付账单生成、对账、付款核销
- 收付款记录与银行对账
- 对账单生成与确认
- 自动计费引擎
- 多币种与汇率管理
- 利润分析
- 提成计算
- 账龄分析与坏账

**不属于本模块：**
- 业务单本身（订单/订舱等）
- 总账与凭证（财务系统层）
- 税务申报（财务系统层）

### 2.4 应收状态机

```

  ↓       ↓         ↓         ↓         ↓
作废   撤回       客户异议   退客户     红冲
```

### 2.5 自动计费引擎

#### 2.5.1 计费规则

| 触发时机 | 计费内容 |
| --- | --- |
| 委托单确认 | 服务项预算 → 应收 |
| 订舱确认 | 海运费 → 应收 |
| 操作完成 | 拖车/装柜费 → 应收 |
| 报关完成 | 报关费 → 应收 |
| 签收完成 | 末端派送 → 应收 |

#### 2.5.2 计费流程

```
触发条件（业务事件）→ 加载委托单服务项 → 比对实际成本
                                                  ↓
                              计算实际应收（可调整）→ 生成应收账单
                                                            ↓
                                                  状态机流转
```

#### 2.5.3 计费策略

| 客户类型 | 计费策略 |
| --- | --- |
| 预付客户 | 委托单确认即生成 |
| 月结客户 | 月结日批量生成 |
| 到付客户 | 货物签收后生成 |

### 2.6 应收对账流程

```
月结日 → 系统生成月度对账单 → 发送给客户 → 客户确认
                                                   ↓
                                        异议 → 协商修改
                                                   ↓
                                        确认 → 通知付款
```

### 2.7 开票

| 开票类型 | 说明 |
| --- | --- |
| 增值税专用发票 | 一般纳税人 |
| 增值税普通发票 | 小规模 |
| 形式发票 | 国外客户 |
| 电子发票 | 数字化 |

### 8.1 利润维度

| 维度 | 说明 |
| --- | --- |

### 8.2 利润计算

```
订单利润 = 订单收入 - 订单成本
订单毛利率 = 订单利润 / 订单收入 × 100%
```

- 成本超预算 10% 触发复核

## 十、信用管理

### 10.1 信用字段

详见客户档案。本模块补充：

| 字段 | 说明 |
| --- | --- |
| credit_limit | 授信额度 |
| credit_period_days | 账期天数 |
| credit_used | 已用额度 |
| credit_available | 可用额度 |
| overdue_amount | 逾期金额 |

### 10.2 信用计算

```
credit_used = Σ未收应收 + 已开票未收
credit_available = credit_limit - credit_used
```

### 10.3 信用控制

| 场景 | 处理 |
| --- | --- |
| 信用充足 | 正常下单 |
| 信用预警（80%） | 提醒销售 |
| 信用超额（100%） | 需主管审批 |
| 信用严重超额（>120%） | 阻止下单 |
| 客户黑名单 | 强制预付 |

### 10.4 信用调整

- 销售申请调整 → 主管审批 → 财务确认
- 系统自动按客户等级调整

## 十七、小结

财务是国际物流的"血液循环"。本模块细化的关键：
1. **应收是命脉**：决定现金流
2. **应付是平衡**：维护合作关系
3. **对账是基础**：双方一致
4. **多币种是国际特性**：汇率管理至关重要
5. **利润分析是核心**：经营决策依据
6. **信用管理是风控**：防范坏账
