# 委托单与订单业务细化 v3.0

> 委托单（订单）是国际物流系统的**业务核心枢纽**——连接询价报价（前序）、订舱操作（中段）、财务结算（后段）、异常处理（全程）。
> 委托单的完整性与准确性决定了整个系统的业务流转效率。

## 一、业务边界与范围

### 1.1 委托单的定位

```
客户需求 ─→ 询价 ─→ 报价 ─→ 采纳 ─→ 【委托单】 ─→ 订舱 ─→ 操作 ─→ 跟踪 ─→ 结算
                              ↑         ↑
                          业务起点     业务中枢
```

| 维度 | 委托单 |
| --- | --- |
| 性质 | 客户与我司的委托合同 |
| 法律效力 | 强（合同级） |
| 数据源 | 报价单（采纳时复用） |
| 数据输出 | 订舱、报关、仓储、财务、跟踪 |

### 1.2 业务范围

**属于本模块：**
- 委托单的创建、确认、修改、取消
- 委托单全生命周期状态管理
- 委托单货物明细与服务项
- 多式联运拆分、订单拆分/合并
- 改单与撤单流程
- 订单利润快照与关账

**不属于本模块：**
- 询价/报价过程（由询价报价模块负责）
- 订舱具体执行（由订舱模块负责）
- 报关申报（由报关模块负责）
- 仓储作业（由仓储模块负责）
- 应收应付生成（由财务模块负责）

### 1.3 与上下游模块的边界

| 上游 | 委托单引用 |
| --- | --- |

### 4.2 货物明细汇总规则

```
总件数 = Σ pkg_qty
总毛重 = Σ weight_kg
总体积 = Σ volume_cbm
总货值 = Σ cargo_value（按本币折算）
```

### 4.3 业务规则

- **至少 1 条货物明细**
- **危险品货物**：必须填 UN 号、危险品等级、包装类别
- **HS 编码**：推荐但非必填（关务录入时强制）
- **单件尺寸**：危险品、超大件、温控货物必填
- **包装类型**：影响打托费用、装柜方案

### 4.4 货物明细操作

| 操作 | 场景 |
| --- | --- |
| 新增 | 委托单确认前 |
| 修改 | 确认后可改单（计改单费） |
| 删除 | 确认后不可删除（仅作废） |
| 拆分 | 同一货品分多票时 |
| 合并 | 多个货品合并（同 HS、同目的） |

## 五、委托单服务项（应收预算）

### 5.1 服务项业务定位

| is_tax_included | ⚪ | 含税 |
| tax_rate | ⚪ | 税率 |
| tax_amount | ⚪ | 税额 |
| source | ✅ | 来源（报价/手工/系统自动） |
| remark | ⚪ | 备注 |

### 5.3 服务项来源

| 来源 | 说明 |
| --- | --- |
| 报价采纳 | 继承自报价明细 |
| 系统自动 | 根据服务需求生成（拖车/报关/仓储） |
| 销售手工 | 销售额外添加 |
| 模板 | 按客户/业务类型默认模板 |

### 5.4 服务项生成规则

```
输入：委托单服务需求 + 业务类型 + 客户 + 起运地/目的地
       ↓
【Step 1】加载必选服务项（如：海运费、报关费）
【Step 2】根据服务需求加载可选服务项（如：需要拖车 → 添加拖车费）
【Step 3】加载客户协议价（如有）
【Step 4】应用客户等级优惠
【Step 5】根据特殊货物加载附加费（如：危险品 → 危险品附加）
       ↓
输出：完整服务项清单
```

### 5.5 服务项可调整

- 销售/操作可修改服务项金额（需说明理由）
- 修改触发审核（金额变动 > 10%）

### 5.6 服务项与实际账单的关系

```
服务项（预估）→ 实际操作 → 应收账单（实际）
差异：可能因实际费用变化（如附加费上调、汇率波动）
```

## 六、委托单状态机

### 6.1 状态列表

| 状态 | 代码 | 含义 |
| --- | --- | --- |
| 草稿 | DRAFT | 编制中，未确认 |
| 待确认 | PENDING_CONFIRM | 客户待确认 |
| 已确认 | CONFIRMED | 客户已确认 |
| 已订舱 | BOOKED | 至少一个订舱完成 |
| 已操作 | IN_OPERATION | 操作中（已发车/已装柜/已报关） |
| 已发运 | SHIPPED | 货物已离开起运地 |
| 在途 | IN_TRANSIT | 运输途中 |
| 已到港 | ARRIVED_PORT | 到达目的港 |
| 清关中 | CLEARING | 清关中 |
| 已派送 | DELIVERING | 派送中 |
| 已签收 | DELIVERED | 客户已签收 |
| 已结算 | SETTLED | 财务结算完成 |
| 已关账 | CLOSED | 关账锁定 |
| 已取消 | CANCELLED | 订单取消 |
| 已作废 | VOID | 系统作废 |

### 6.2 状态机图

```
草稿 ─→ 待确认 ─→ 已确认 ─→ 已订舱 ─→ 已操作 ─→ 已发运
  ↓       ↓         ↓         ↓         ↓
取消    拒绝     改单/取消  改单/取消   在途
          ↓         ↓         ↓
       已作废    已取消     已签收
                              ↓
                          已结算 → 已关账
```

### 6.3 状态转换规则

| 起始状态 | 目标状态 | 触发条件 | 操作权限 |
| --- | --- | --- | --- |
| 草稿 | 待确认 | 销售提交 | 销售 |
| 草稿 | 已取消 | 销售取消 | 销售 |
| 待确认 | 已确认 | 客户确认 | 客户/销售 |
| 待确认 | 草稿 | 客户要求修改 | 销售 |
| 待确认 | 已作废 | 超时未确认 | 系统/销售 |
| 已确认 | 已订舱 | 至少 1 个订舱完成 | 系统/操作 |
| 已确认 | 已取消 | 客户取消（计费） | 销售主管 |
| 已订舱 | 已操作 | 开始操作 | 操作 |
| 已订舱 | 已取消 | 客户取消 | 销售主管 |
| 已操作 | 已发运 | 货物离开起运地 | 系统/操作 |
| 已发运 | 在途 | 跟踪事件触发 | 系统 |
| 在途 | 已到港 | 到达目的港 | 系统 |
| 已到港 | 清关中 | 报关申报 | 系统/关务 |
| 清关中 | 已派送 | 清关放行 | 系统/操作 |
| 已派送 | 已签收 | 客户签收 | 系统 |
| 已签收 | 已结算 | 应收账单生成 | 系统/财务 |
| 已结算 | 已关账 | 财务关账 | 财务主管 |

### 6.4 状态自动触发

| 自动触发 | 触发事件 |
| --- | --- |
| 已订舱 | 第一个订舱确认（`booking_status = CONFIRMED`） |
| 已操作 | 任意操作开始（如拖车派车） |
| 已发运 | 跟踪事件"已开船/已起飞" |
| 在途 | 跟踪事件"在途" |
| 已到港 | 跟踪事件"已到港" |
| 清关中 | 报关单"已申报" |
| 已派送 | 跟踪事件"已派送" |
| 已签收 | 跟踪事件"已签收" |

## 七、委托单生命周期

### 7.1 创建阶段

#### 7.1.1 创建方式

| 方式 | 触发 | 数据来源 |
| --- | --- | --- |
| 报价采纳 | 客户采纳报价 | 报价单数据 |
| 销售代客 | 销售录入 | 手工 + 历史模板 |
| 客户自助 | 客户门户下单 | 客户填表 |
| 商机转化 | CRM 商机推进 | 商机数据 |
| API 对接 | 电商平台推送 | API 数据 |

#### 7.1.2 创建流程

```
触发创建 → 加载客户档案（信用、账期、币种）
       → 加载运输需求
       → 加载货物明细
       → 自动生成服务项
       → 计算预估金额
       → 校验信用、库存等
       → 保存草稿
       ↓
   销售提交 → 进入待确认状态
```

#### 7.1.3 创建时校验

| 校验项 | 说明 |
| --- | --- |
| 客户有效性 | 客户非冻结/黑名单 |
| 客户信用 | 可用信用 ≥ 本单预估金额 |
| 货量合理性 | 重量体积与件数匹配 |
| 危险品资质 | 客户有相应危险品资质 |
| 海关资质 | AEO/EORI 校验 |
| HS 编码 | 必填项与税率 |

### 7.2 确认阶段

#### 7.2.1 确认流程

```
客户/销售确认 → 系统校验所有必填项 → 状态置为"已确认"
                                        ↓
                              生成订舱任务（按业务类型）
                              生成跟踪号
                              锁定客户信用额度
                              触发通知（操作员）
```

#### 7.2.2 确认后自动动作

- 客户信用额度临时锁定（应收预估金额）
- 生成内部单号（无）
- 触发邮件通知操作员
- 生成客户确认邮件
- 启动 SLA 计时

### 7.3 订舱阶段

#### 7.3.1 与订舱的衔接

```
委托单确认 → 自动/手工生成订舱 → 订舱确认 → 委托单状态→"已订舱"
                              ↓
                       订舱失败 → 状态回滚 → 重订
```

#### 7.3.2 多段订舱处理

| 业务类型 | 订舱数 | 处理 |
| --- | --- | --- |
| 海运 FCL | 1 | 单订舱 |
| 多式联运 | 多 | 每段独立订舱 + 主单串联 |
| 转口 | 2 | 第一段+第二段独立订舱 |

### 7.4 操作阶段

操作阶段是国际物流的"重头戏"，包括拖车、装柜、报关、补料等（详见订舱操作模块）。

委托单在此阶段记录关键节点。

### 7.5 发运与在途

```
货物离开起运地 → 跟踪事件"已开船/已起飞" → 委托单状态→"已发运"
           ↓
       跟踪事件持续更新 → 状态保持"在途"
           ↓
       到达目的港 → 状态→"已到港"
```

### 7.6 清关与派送

```
到港 → 清关（报关模块负责）→ 放行 → 派送（操作模块负责）→ 签收
```

### 7.7 签收与结算

```
客户签收 → 状态→"已签收"
        ↓
   财务模块生成应收账单
        ↓
   与客户对账 → 客户确认 → 收款 → 状态→"已结算"
        ↓
   关账 → 状态→"已关账"
```

### 7.8 归档

- 委托单关账后进入归档
- 归档数据保留 5-10 年（合规要求）
- 仅可查询，不可修改

## 八、改单与撤单

### 8.1 改单（Amendment）

#### 8.1.1 改单场景

| 场景 | 业务影响 | 改单类型 |
| --- | --- | --- |
| 修改货物明细 | 提单、报关单需更新 | 货物改单 |
| 修改起运港/目的港 | 订舱、运价、路线变更 | 路线改单 |
| 修改贸易条款 | 服务范围变更 | 服务改单 |
| 修改柜型/数量 | 订舱需调整 | 订舱改单 |
| 修改客户信息 | 提单发货人/收货人变更 | 主体改单 |
| 修改收货人 | 提单变更 | 提单改单 |
| 修改 ETD/ETA | 订舱时间调整 | 时间改单 |

#### 8.1.2 改单规则

| 状态 | 改单限制 |
| --- | --- |
| 草稿 | 任意修改，不计费 |
| 待确认 | 退回草稿后修改 |
| 已确认 | 计改单费，可改 |
| 已订舱 | 计改单费 + 承运人改单费 |
| 已操作 | 计改单费 + 复杂处理 |
| 已发运 | 部分可改（如收货人），计费高 |
| 已签收 | 不可改 |
| 已结算/已关账 | 不可改 |

#### 8.1.3 改单流程

```
发起改单 → 选择改单项 → 记录改单原因 → 计算改单费用
       → 主管审核（如金额>阈值）→ 客户确认（如需）
       → 执行修改 → 生成版本号 +1 → 通知相关方
```

#### 8.1.4 改单计费

| 改单类型 | 改单费 |
| --- | --- |
| 货物明细 | 200-500 元/票 |
| 路线变更 | 500-2000 元/票 |
| 提单变更 | 500-2000 元/票 + 承运人收费 |
| 收货人变更 | 200-1000 元/票 |
| 订舱调整 | 承运人改单费转嫁 |

### 8.2 撤单（Cancel）

#### 8.2.1 撤单条件

| 状态 | 可撤单 | 撤单费 |
| --- | --- | --- |
| 草稿 | ✅ | 无 |
| 待确认 | ✅ | 无 |
| 已确认 | ✅ | 计退单费 |
| 已订舱 | ✅（可能） | 退单费 + 承运人退舱费 |
| 已操作 | ⚠️（需评估） | 高额费用 |
| 已发运 | ❌（不可撤） | - |
| 已签收 | ❌ | - |

#### 8.2.2 撤单流程

```
发起撤单 → 选择撤单原因 → 系统计算撤单费用
       → 主管审核 → 客户确认 → 执行撤单
                              ↓
                  订舱取消 → 状态置为"已取消"
                  财务处理 → 应收应付调整
                  通知客户 → 归档
```

#### 8.2.3 撤单费用构成

| 费用项 | 说明 |
| --- | --- |
| 退单手续费 | 我司收取（如 500 元/票） |
| 承运人退舱费 | 承运人收取（按合约） |
| 已发生成本 | 如已发生的拖车费、报关费 |
| 应收款项调整 | 应收账单生成 |

## 九、多式联运拆分

### 9.1 多式联运定义

```
一段货物运输涉及多种运输方式（陆运+海运+陆运）
每段独立订舱、独立费用、独立跟踪
但作为同一个"业务订单"管理
```

### 9.2 多式联运字段

主委托单（Master Order）：

| 字段 | 说明 |
| --- | --- |
| is_multimodal | 是否多式联运 |
| transport_segments | 段数（如 3 段：陆运+海运+陆运） |
| master_order_no | 主单号 |

段委托单（Segment Order）：

| 字段 | 说明 |
| --- | --- |
| parent_order_id | 父委托单 |
| segment_no | 段号（1/2/3） |
| segment_type | 段类型（陆运/海运/空运/铁路） |

### 9.3 段状态独立管理

- 每段独立的状态机
- 整体进度 = 各段综合状态
- 任意一段异常触发主单异常

### 9.4 多式联运编号


## 十、订单拆分与合并

### 10.1 拆分场景

| 拆分原因 | 业务影响 |
| --- | --- |
| 客户分批提货 | 拆为多票 |
| 不同 HS 编码分票 | 便于报关 |
| 不同目的港分票 | 便于目的港清关 |
| 不同运输方式 | 多式联运段的反向拆分 |
| 不同柜型混装 | 拆分为不同柜型 |

### 10.2 拆分规则

```
原委托单 → 拆分为 N 个子委托单
- 子委托单继承主委托单大部分数据
- 独立编号、独立跟踪、独立结算
- 主委托单状态 = 合并子委托单状态
```

### 10.3 合并场景

| 合并原因 | 业务影响 |
| --- | --- |
| 多票货物同船 | 节省海运费 |
| 多票货物同客户同时段 | 简化操作 |
| LCL 多客户拼箱 | 拼成整柜 |

### 10.4 合并规则

```
N 个委托单 → 合并为 1 个
- 取最早 ETD
- 客户、起运港、目的港一致
- 不同时期币种需转换
- 合并后操作统一
```

## 十八、关键设计要点小结

1. **委托单是业务中枢**：连接报价、订舱、报关、仓储、财务、跟踪所有模块
2. **状态机是核心**：14 个状态覆盖完整生命周期
3. **货物明细和服务项是基础数据**：决定了后续所有操作
4. **改单/撤单是高频场景**：必须有清晰的规则和计费标准
5. **多式联运是特殊形态**：需要主单+段单的双层结构
6. **订单关账是闭环**：所有业务数据在此锁定
7. **SLA 是服务质量保障**：每个阶段都有明确时效要求
8. **利润快照是经营分析基础**：从下单到关账多次快照

## 十九、与下一模块的衔接

委托单确认后进入操作阶段，下一步：进入 **任务 #4：订舱与操作业务细化**。

订舱模块将基于委托单：
- 加载运输需求（起运港、目的港、柜型、货物）
- 匹配船公司/航司航线
- 生成订舱单（关联委托单）
- 管理截关/截港时间
- 触发提单、补料、集装箱动态
