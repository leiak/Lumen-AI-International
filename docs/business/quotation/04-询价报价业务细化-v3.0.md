# 询价与报价业务细化 v3.0

> 询价与报价是业务起点，决定了能否拿下订单、利润多少、客户体验的第一印象。
> 本文档对询价、报价、运价库、附加费库、客户协议价、报价计算引擎进行**业务级**深化设计。

---

每个业务模块按以下结构细化：

1. **业务边界**

## 一、业务边界与范围

### 1.1 业务定位

```
客户需求 ─→ 询价 ─→ 报价 ─→ 采纳 ─→ 委托单 ─→ 订舱 ─→ ...
                   ↑      ↓
                 运价库/附加费/协议价 计算引擎
```

| 模块 | 定位 | 输入 | 输出 |
| --- | --- | --- | --- |
| 询价 | 客户需求采集 | 客户、运输需求、货物信息 | 询价单 |
| 报价 | 价格计算与呈现 | 询价、运价、附加费、协议价 | 报价单（PDF） |
| 运价库 | 基础价格存储 | 承运人合约价 | 可查询运价 |
| 附加费库 | 杂费存储 | 承运人/航线杂费 | 可计算杂费 |
| 协议价 | 客户特惠价 | 客户合约 | 优先级最高的报价基础 |

### 1.2 业务范围

**属于本模块：**
- 客户询价录入（销售/客户自助）
- 报价单生成、审核、发送、采纳
- 运价、附加费、协议价的维护
- 报价转委托单
- 报价命中率与时效分析

**不属于本模块：**
- 委托单生成（订单层）
- 订舱与海运费支付（订舱层）
- 财务结算（财务层）
- 客户分级（基础资料层）

### 1.3 询价/报价 vs 委托单的关系

| 维度 | 询价/报价 | 委托单 |
| --- | --- | --- |
| 性质 | 价格协商 | 委托操作 |
| 法律效力 | 较弱（要约） | 强（合同） |
| 时效 | 报价有效期 7-30 天 | 长期 |
| 触发 | 客户问价 | 客户采纳并委托 |
| 输出 | 报价单 | 委托单 + 服务项 |

> **关键原则**：报价单被客户采纳后，可一键转为委托单（复用 80% 数据）。

### 2.4 询价状态机

```
创建 ─→ 已分配 ─→ 报价中 ─→ 已报价 ─→ 已采纳 ─→ 已关闭
   ↓       ↓        ↓         ↓
 撤回    转销售    超时      已过期
         退回        ↓
                  已失效
```

| 状态 | 含义 | 允许操作 |
| --- | --- | --- |
| 待分配 | 创建未分配销售 | 自动分配/手动分配 |
| 已分配 | 已分配销售 | 接受/退回/转销售 |
| 报价中 | 销售处理中 | 暂存报价/发起报价 |
| 已报价 | 报价单已发送 | 接受/拒绝/过期 |
| 已采纳 | 客户采纳 | 转委托单/关闭 |
| 已拒绝 | 客户拒绝 | 关闭 |
| 已过期 | 超过报价有效期 | 关闭 |
| 已撤回 | 客户撤回询价 | 关闭 |
| 已关闭 | 流程结束 | 归档 |

### 2.5 询价 SLA 管理

| 类型 | 响应时间 | 备注 |
| --- | --- | --- |
| 紧急询价 | ≤2 小时 | VIP客户、大客户、紧急货 |
| 常规询价 | ≤4 小时 | 正常工作时段 |
| 慢速询价 | ≤24 小时 | 非紧急、可批量 |

> **SLA 触发**：
> - 超时 30 分钟：提醒销售
> - 超时：提醒销售主管
> - 超时 50%：通知运营经理
> - 超 SLA：记录并纳入销售考核

### 2.6 询价分配规则

#### 2.6.1 自动分配（默认）

```
按客户归属销售优先 → 按销售负载均衡 → 按区域专长
```

- 同一客户的询价自动分配给该客户归属销售
- 归属销售请假/忙时分配给销售组其他成员
- 按销售当月询价量均衡

#### 2.6.2 手动分配

主管可在询价池中手动分配给指定销售。

### 2.7 询价流程

#### 2.7.1 客户自助询价流程

```
客户登录客户门户 → 填写询价单 → 提交 → 系统自动分配销售 → 销售响应
                                                    ↓
                                              自动报价 or 人工报价
```

#### 2.7.2 销售代客询价流程

```
销售接客户电话 → 录入询价单 → 自动分配给自己 → 处理 → 报价
```

#### 2.7.3 询价池分配流程

```
新询价 → 询价池（待分配）→ 自动分配引擎 → 销售工作台 → 销售响应
```

### 2.8 询价 SLA 看板

- 待处理询价数（按销售）
- 超时询价数（按销售）
- 平均响应时长
- 紧急询价响应率

### 3.4 报价状态机

```
草稿 ─→ 待审核 ─→ 已审核 ─→ 已发送 ─→ 客户已读 ─→ 已采纳 ─→ 已关闭
  ↓       ↓         ↓         ↓          ↓           ↓
废弃   审核驳回   退回销售    撤回      已过期      已拒绝
                                            ↓
                                          转委托单
```

| 状态 | 含义 | 允许操作 |
| --- | --- | --- |
| 草稿 | 销售编制中 | 编辑/暂存 |
| 待审核 | 提交待审核 | 审核/驳回 |
| 审核驳回 | 主管驳回 | 修改后重新提交 |
| 已审核 | 审核通过 | 发送客户/撤回 |
| 已发送 | 客户收到 | 撤回/跟进 |
| 客户已读 | 客户已查看 | 跟进 |
| 已采纳 | 客户接受 | 转委托单 |
| 已拒绝 | 客户拒绝 | 关闭/重新报价 |
| 已过期 | 超有效期 | 关闭/重新报价 |
| 已撤回 | 销售撤回 | 编辑/关闭 |
| 已关闭 | 流程结束 | 归档 |

### 3.5 报价流程

#### 3.5.1 销售报价流程

```
销售接受询价 → 调用报价计算引擎 → 生成报价草稿 → 检查报价完整性
                                                      ↓
                                            销售修改调整 → 提交审核
                                                              ↓
                                          主管审核 ─→ 审核通过 → 发送给客户
                                                       ↓
                                                  审核驳回 → 退回销售修改
```

#### 3.5.2 自动报价流程（系统直出）

```
客户在线询价 → 系统自动匹配运价+附加费+协议价 → 生成报价单
                                                  ↓
                                          直接发送客户（无需审核）
                                          或 大额订单触发审核
```

#### 3.5.3 报价审核规则（可配置）

| 触发条件 | 审核人 |
| --- | --- |
| 报价金额 > 10万 | 销售主管 |
| 报价金额 > 50万 | 销售经理 |
| 报价毛利率 < 5% | 销售主管 |
| 报价毛利率 < 0% | 销售经理 |
| VIP 客户报价 | 销售主管 |
| 异常报价（偏离市场 >30%） | 销售主管 |

### 3.6 报价有效期管理

| 客户类型 | 默认有效期 |
| --- | --- |
| VIP | 30 天 |
| A 级 | 21 天 |
| B 级 | 14 天 |
| C 级 | 7 天 |
| 散客 | 7 天 |

- **有效期到期前 3 天**：提醒销售跟进
- **到期当日**：自动标记"已过期"
- **延期报价**：可由销售申请延期（需主管审批）

### 3.8 报价采纳与转委托

#### 3.8.1 采纳流程

```
客户在线/邮件采纳 → 销售确认 → 生成委托单草稿 → 客户确认 → 委托单生效
                                                          ↓
                                                关联回原询价与报价单
```

#### 3.8.2 转委托数据复用

- 客户、运输需求、货物信息自动继承
- 服务项与费用项作为应收预算
- 报价有效期结束后不可采纳

### 3.9 报价修订

- 销售可基于原报价生成新版本（version +1）
- 历史版本保留可查
- 同一询价可有多个报价版本

## 四、运价库（Base Rate）

### 4.1 业务定位

运价库是**最基础的价格来源**，由销售/商务从承运人合约、公开市场数据维护而来。

### 4.2 运价分类

| 维度 | 分类 |
| --- | --- |
| 运输方式 | 海运/空运/铁路/陆运 |
| 计价方式 | 整柜（CBM 计费）/散货（KG+CBM 取大）/空运（重量段） |
| 价格类型 | 合约价（与承运人签）/ 即期价（市场浮动） |
| 区域 | 区域定价（如远东-北非） |

### 4.3 运价字段详解

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| rate_code | ✅ | 运价编码（自动） |
| rate_type | ✅ | 海运/空运/铁路/陆运 |
| carrier_id | ✅ | 承运人 |
| contract_no | ⚪ | 合约号 |
| origin_port_id | ✅ | 起运港 |
| dest_port_id | ✅ | 目的港 |
| transit_port_ids | ⚪ | 中转港 |
| container_type_code | ✅ | 柜型（空运则为重量段） |
| weight_range_min/max | ⚪ | 重量段（空运用） |
| cbm_range_min/max | ⚪ | 体积段 |
| base_price | ✅ | 基础价 |
| currency_code | ✅ | 币种 |
| price_basis | ✅ | PER_TEU / PER_BOX / PER_KG / PER_CBM |
| valid_from | ✅ | 生效日期 |
| valid_to | ✅ | 失效日期 |
| rate_status | ✅ | 启用/停用/即将过期 |
| min_quantity | ⚪ | 最小订量 |
| max_quantity | ⚪ | 最大订量 |
| remarks | ⚪ | 备注 |

### 4.4 运价匹配算法

```
输入：业务类型 + 起运港 + 目的港 + 柜型 + 数量 + 重量 + 体积 + 日期
输出：基础海运费

匹配逻辑：
1. 优先匹配：承运人 + 起运港 + 目的港 + 柜型 + 数量段 + 日期范围内
2. 备选匹配：承运人 + 起运港 + 目的港 + 柜型 + 日期范围内
3. 兜底匹配：起运港 + 目的港 + 柜型 + 日期范围内（多承运人对比）
4. 无匹配：提示销售手工报价
```

### 4.5 运价生效优先级

| 优先级 | 来源 |
| --- | --- |
| 1（最高） | 客户协议价（指定客户 + 指定航线） |
| 2 | 承运人合约价（指定承运人） |
| 3 | 公开市场运价（市场即时） |
| 4 | 兜底手工报价 |

### 4.6 运价维护流程

#### 4.6.1 新增运价

```
商务洽谈 → 录入合约价 → 主管审核 → 生效 → 同步至报价引擎
```

#### 4.6.2 运价调整

```
承运人通知调价 → 录入新价格 → 旧价格自动到期 → 主管审核 → 生效
```

#### 4.6.3 运价过期管理

- 到期前 30 天：提醒商务
- 到期当日：自动停用
- 历史价格保留 5 年（合规）

### 4.7 运价与其他模块的交互

- 报价 → 运价匹配与计算
- 委托单 → 海运费基础
- 应付账单 → 实际结算（与合约价可能不一致）
- 财务分析 → 运价成本对比

## 五、附加费库（Surcharge）

### 5.1 业务定位

附加费是**除基础运费外的杂费**，来自承运人、港口、海关、特殊服务等多个来源。

### 5.2 附加费分类

| 大类 | 费用项 |
| --- | --- |
| 承运人附加费 | BAF/THC/ISPS/CAF/OWS/PCS/SEAL/旺季/低硫 |
| 港口附加费 | DETENTION/DEMURRAGE/THC/EBS |
| 海关附加费 | 查验费/查验掏箱费/滞报金 |
| 特殊货物附加费 | 危险品/温控/超大件/私人标签 |
| 服务附加费 | 改单/电放/分票/退单 |
| 杂项 | 文件费/快递费/抄单费 |

### 5.3 附加费字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| surcharge_code | ✅ | 附加费代码 |
| surcharge_name | ✅ | 名称 |
| surcharge_category | ✅ | 大类 |
| carrier_id | ⚪ | 承运人（适用于承运人附加费） |
| port_id | ⚪ | 适用港 |
| origin_port_id | ⚪ | 起运港（可空） |
| dest_port_id | ⚪ | 目的港（可空） |
| container_type_code | ⚪ | 适用柜型 |
| calc_type | ✅ | FIXED_AMOUNT（固定金额）/ PERCENTAGE（百分比）/ PER_UNIT（按量） |
| amount | ✅ | 金额或比例 |
| currency_code | ✅ | 币种 |
| valid_from | ✅ | 生效日期 |
| valid_to | ✅ | 失效日期 |
| auto_add | ✅ | 报价时是否自动加入 |
| is_mandatory | ✅ | 是否必选 |
| priority | ✅ | 加载优先级 |
| remarks | ⚪ | 备注 |

### 5.4 附加费计算方式

| calc_type | 计算示例 |
| --- | --- |
| FIXED_AMOUNT | 金额 = fixed_value |
| PERCENTAGE | 金额 = base × percentage |
| PER_BOX | 金额 = qty × value（按柜数） |
| PER_KG | 金额 = weight × value（按重量） |
| PER_CBM | 金额 = volume × value（按体积） |
| PER_SHIPMENT | 金额 = value（每票固定） |

### 5.5 附加费触发规则

| 规则 | 说明 |
| --- | --- |
| 自动加载 | 报价时按航线/承运人/日期自动匹配 |
| 手动加载 | 销售根据客户特殊需求手动添加 |
| 条件加载 | 当满足某条件才加载（如危险品 → 危险品附加） |

### 5.6 附加费状态机

```
筹备中 ─→ 启用 ─→ 即将过期 ─→ 过期 ─→ 归档
            ↓
          停用（暂停使用）
```

### 5.7 附加费管理流程

```
承运人/港口通知 → 录入系统 → 主管审核 → 启用 → 同步至报价引擎
              ↓
          价格调整 → 录入新价格 → 旧价格到期
```

### 5.8 附加费与运价的差异

| 维度 | 运价 | 附加费 |
| --- | --- | --- |
| 数量 | 少（一个航线一个基础价） | 多（一个航线可能有 10+ 项） |
| 变化频率 | 低（合约期 3-12 个月） | 高（按月/季度调整） |
| 来源 | 承运人合约 | 承运人/港口/海关/服务 |
| 重要性 | 决定基础成本 | 影响总成本 30-50% |

### 6.1 业务定位

| 优先级 | 来源 |
| --- | --- |

### 6.5 协议价管理流程

```

```


#### 6.5.3 协议到期

- 到期前 60 天：提醒销售
- 到期前 30 天：主管预警
- 到期当日：自动停用
- 到期后 30 天内可延期

### 6.6 协议价与报价的关系

```
客户 X 询价（上海 → 洛杉矶 40HQ）
→ 报价引擎匹配：
   1. 客户协议价（X-客户-2026年度）→ 命中 → 使用
   2. 否则承运人合约价 → 备选
   3. 否则市场运价 → 兜底
```

## 七、报价计算引擎

### 7.1 报价计算流程

```
输入：询价信息 + 客户 + 货物
       ↓
【Step 1】匹配基础运价
       ↓ 按客户协议价 > 承运人合约价 > 市场运价
       ↓
【Step 2】自动加载附加费
       ↓ 按航线 + 承运人 + 货物特性
       ↓
【Step 3】加载手工费用项
       ↓ 销售根据客户需求添加
       ↓
【Step 4】应用优惠/折扣
       ↓ 按客户等级 + 协议优惠
       ↓
【Step 5】计算小计、税额、总计
       ↓
【Step 6】计算毛利、毛利率
       ↓
输出：报价单（含明细）
```

### 7.2 报价项加载规则

| 加载方式 | 来源 | 触发条件 |
| --- | --- | --- |
| 自动（基础费） | 运价库 | 询价提交时 |
| 自动（附加费） | 附加费库 | 按航线/承运人匹配 |
| 自动（客户协议） | 协议价 | 客户+航线匹配 |
| 手工（销售） | 销售添加 | 销售判断 |
| 手工（增值服务） | 服务项模板 | 客户需求 |

### 7.3 成本与售价计算

```
成本 = Σ (每项费用成本)
售价 = Σ (每项费用售价)
毛利 = 售价 - 成本
毛利率 = 毛利 / 售价 × 100%
```

### 7.4 利润控制

- **报价毛利率阈值**：
  - 海运 FCL：≥8%
  - 空运：≥10%
  - 铁路：≥8%
  - 陆运：≥12%
- **低于阈值**：触发主管审核
- **负毛利**：触发经理审批

### 7.5 报价价格策略

| 客户等级 | 价格策略 |
| --- | --- |
| VIP | 协议价（最低） |
| A 级 | 协议价（次低） |
| B 级 | 合约价 + 优惠 3-5% |
| C 级 | 合约价（标准） |
| 散客 | 市场价 + 加价 5-10% |

## 十四、关键设计要点小结

1. **询价与报价是业务的"漏斗顶端"**：决定能否获取订单、利润率、客户体验
2. **运价+附加费+协议价是报价的三大基石**：必须数据准确、更新及时、维护规范
3. **协议价优先级最高**：大客户维护的核心
4. **报价计算引擎要可扩展**：支持新费用类型、新计价方式
5. **报价单 PDF 是客户决策的窗口**：模板规范、品牌统一
6. **报价分析是销售管理的核心**：命中率、时效、毛利率多维分析
7. **报价与委托单的衔接要无缝**：一键采纳、数据复用

## 十五、与下一模块的衔接

报价单被客户采纳后转**委托单**。下一步：进入 **任务 #3：委托单与订单业务细化**。

委托单将沿用：

- 服务项与费用项（作为应收预算）
- 销售归属、协议价关联（继承自报价）
