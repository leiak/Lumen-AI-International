> 跟踪与异常是国际物流的"神经系统"——通过实时事件采集、智能异常预警、主动客户沟通，让客户全程掌控货物状态。

## 一、业务边界与范围

### 1.1 跟踪的业务定位

```
订舱/操作 ─→ 触发事件 ─→ 【跟踪系统】 ─→ 时间线 ─→ 客户可见
                                      ↓
                                异常预警 ─→ 工单 ─→ 处理
```

| 模块 | 业务范围 |
| --- | --- |
| 跟踪事件 | 节点事件采集与时间线 |
| 异常事件 | 异常识别与处理 |
| ETA 预测 | 预计到达时间计算 |
| 客户跟踪 | 客户可见的跟踪链接 |
| 自动通知 | 节点/异常自动通知 |

### 1.2 业务范围

**属于本模块：**
- 跟踪事件采集（多源：手工/EDI/API/IoT/客户/承运人）
- 跟踪时间线生成
- 异常识别与分类
- 异常处理流程
- ETA 智能预测
- 客户可见跟踪页面
- 自动通知触发

**不属于本模块：**
- 物理操作执行（订舱模块）
- 报关申报（关务模块）
- 财务结算（财务模块）
- 工单处理流程（客服模块）

## 二、跟踪事件（Tracking Event）

### 2.1 事件分类

| 维度 | 分类 |
| --- | --- |
| 业务类型 | 拖车 / 订舱 / 装柜 / 报关 / 海运 / 空运 / 铁路 / 陆运 / 清关 / 派送 / 仓储 |
| 事件性质 | 正常事件 / 异常事件 |
| 来源 | 手工 / EDI / API / 客户 / IoT / 邮件 / 承运人 |
| 影响范围 | 节点级 / 订单级 |

### 2.2 事件字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| id | ✅ | 主键 |
| event_no | ✅ | 事件号 |
| business_type | ✅ | 业务类型 |
| related_id | ✅ | 关联业务单 ID |
| related_no | ✅ | 关联业务单号 |
| container_no | ⚪ | 柜号 |
| bl_no | ⚪ | 提单号 |
| event_type | ✅ | 事件类型（详见下方） |
| event_desc | ✅ | 事件描述 |
| location_id | ⚪ | 发生地点 |
| location_text | ⚪ | 文本地点 |
| event_time | ✅ | 事件时间 |
| source | ✅ | 来源 |
| is_exception | ✅ | 是否异常 |
| exception_type | ⚪ | 异常类型 |
| reported_by | ⚪ | 上报人 |
| remark | ⚪ | 备注 |
| created_at | ✅ | 录入时间 |

### 2.3 事件类型全量

**拖车段**
- TRUCK_DISPATCHED（已派车）
- TRUCK_ARRIVED（已到达提货地）
- TRUCK_PICKED_UP（已提货）
- TRUCK_LOADED（已装车）
- TRUCK_IN_TRANSIT（运输中）
- TRUCK_DELIVERED（已送达）

**装柜段**
- CONTAINER_PICKED_UP（已提柜）
- CONTAINER_LOADED（已装柜）
- CONTAINER_SEALED（已封志）

**进港段**
- CONTAINER_GATE_IN（已进港）
- CUSTOMS_DECLARED（已报关）
- CUSTOMS_RELEASED（已放行）
- CUSTOMS_HOLD（海关扣留）

**海运段**
- VESSEL_LOADED（已装船）
- VESSEL_DEPARTED（已开船）
- VESSEL_IN_TRANSIT（在途）
- VESSEL_TRANSIT_PORT（中转港）
- VESSEL_ARRIVED（已到港）
- VESSEL_DISCHARGED（已卸船）

**空运段**
- AWB_RECEIVED（运单接收）
- SECURITY_CLEARED（安检通过）
- FLIGHT_LOADED（已装机）
- FLIGHT_DEPARTED（已起飞）
- FLIGHT_ARRIVED（已到达）
- AWB_DELIVERED（运单提取）

**铁路段**
- TRAIN_LOADED（已装车）
- TRAIN_DEPARTED（已发车）
- TRAIN_AT_BORDER（边境等待）
- TRAIN_CLEARED_BORDER（已清关过境）
- TRAIN_ARRIVED（已到达）

**末端派送**
- DELIVERY_DISPATCHED（已派送）
- DELIVERY_IN_PROGRESS（派送中）
- DELIVERY_ARRIVED（已到达收货地）
- DELIVERY_SIGNED（已签收）
- DELIVERY_FAILED（派送失败）

**特殊**
- EXCEPTION_OCCURRED（异常发生）
- ORDER_CANCELLED（订单取消）
- ORDER_AMENDED（订单修改）

### 2.4 事件状态机

每个事件本身没有状态机，但事件触发的关联业务单状态会变化。

### 2.5 事件来源与采集

| 来源 | 采集方式 | 实时性 | 准确性 |
| --- | --- | --- | --- |
| 手工录入 | 操作员手动 | 准实时 | 依赖人工 |
| EDI（IFTSTA） | 自动接收 | 高 | 高 |
| 承运人 API | 自动轮询 | 实时 | 高 |
| 客户反馈 | 客户自助 | 实时 | 中 |
| IoT/GPS | 自动上报 | 实时 | 高 |
| 邮件解析 | 自动解析 | 准实时 | 中 |
| 微信机器人 | 关键词触发 | 准实时 | 中 |

### 2.6 事件去重与合并

- 同事件来源同一时间同一描述 → 去重
- 同业务类型多源事件 → 取最早时间
- 异常事件 → 优先展示

### 2.7 跟踪时间线

#### 2.7.1 时间线生成

```
按 event_time 排序 → 按事件类型分组 → 按地点串联 → 输出时间线
```

#### 2.7.2 时间线展示

- 按时间正序（默认）/ 倒序
- 关键节点高亮
- 异常事件红色标识
- 预计事件灰色标识

#### 2.7.3 时间线维度

| 维度 | 说明 |
| --- | --- |
| 完整时间线 | 包含所有事件 |
| 关键节点时间线 | 仅显示关键节点 |
| 简化时间线 | 仅显示客户可见节点 |

## 三、异常事件（Exception Event）

### 3.1 异常分类

| 大类 | 细分 |
| --- | --- |
| 延误类 | 船期延误、航班延误、铁路延误、派送延误 |
| 改派类 | 改港、改船、改航班、改路线 |
| 货损类 | 货损、丢失、破损、污染 |
| 海关类 | 查验、退关、扣货、单证问题 |
| 危险品类 | 危险品异常、泄漏、爆炸 |
| 客户类 | 拒签、地址错误、收件人不在 |
| 不可抗力 | 自然灾害、罢工、战争 |
| 其他 | 通讯异常、文件遗失 |

### 3.2 异常字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| exception_no | ✅ | 异常单号 |
| business_type | ✅ | 业务类型 |
| related_id | ✅ | 关联业务单 ID |
| related_no | ✅ | 关联业务单号 |
| container_no | ⚪ | 柜号 |
| bl_no | ⚪ | 提单号 |
| exception_type | ✅ | 异常类型 |
| exception_level | ✅ | 高/中/低 |
| description | ✅ | 异常描述 |
| occurred_at | ✅ | 发生时间 |
| discovered_at | ✅ | 发现时间 |
| root_cause | ⚪ | 根本原因 |
| responsibility | ✅ | 客户/承运人/我司/海关/不可抗力 |
| solution | ⚪ | 处理方案 |
| compensation_amount | ⚪ | 赔付金额 |
| status | ✅ | 状态机 |
| handler_id | ⚪ | 处理人 |
| closed_at | ⚪ | 关闭时间 |

### 3.3 异常状态机

```
待处理 ─→ 处理中 ─→ 已解决 ─→ 已关闭
   ↓         ↓         ↓
 升级    转工单     撤销/重新打开
```

| 状态 | 含义 |
| --- | --- |
| 待处理 | 异常刚发现 |
| 处理中 | 已分配处理人 |
| 已解决 | 问题解决 |
| 已关闭 | 流程结束 |
| 转工单 | 升级到工单系统 |
| 升级 | 上级介入 |

### 3.4 异常等级

| 等级 | 判定 | 响应时间 |
| --- | --- | --- |
| 高 | 货损、扣货、危险品泄漏、客户重大损失 | ≤1 小时 |
| 中 | 延误、查验、退关 | ≤4 小时 |
| 低 | 文件遗失、轻微延误 | ≤24 小时 |

### 3.5 异常处理流程

```
异常识别（自动/手工）→ 创建异常事件 → 等级判定 → 通知处理人
                                                ↓
                                          处理人响应
                                                ↓
                                    调查原因 → 制定方案 → 执行
                                                ↓
                                            客户沟通
                                                ↓
                                          解决/关闭 → 复盘归档
```

### 3.6 责任判定

| 责任方 | 应对 |
| --- | --- |
| 客户 | 沟通、协商、可能费用承担 |
| 承运人 | 向承运人索赔 |
| 我司 | 我司承担赔付 |
| 海关 | 配合处理 |
| 不可抗力 | 走保险、共同承担 |

### 3.7 异常 SLA

| 异常等级 | 首次响应 | 解决时长 |
| --- | --- | --- |
| 高 | 15 分钟 | 4 小时 |
| 中 | 1 小时 | 24 小时 |
| 低 | 4 小时 | 72 小时 |

## 四、ETA 预测

### 4.1 ETA 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| container_no | ✅ | 柜号 |
| bl_no | ✅ | 提单 |
| carrier_id | ✅ | 承运人 |
| route_id | ✅ | 航线 |
| origin_etd | ✅ | 起运港预计开船 |
| current_eta | ✅ | 当前预计到达 |
| predicted_eta | ✅ | AI 预测到达时间 |
| confidence | ✅ | 置信度（0-100%） |
| model_version | ✅ | 预测模型版本 |
| updated_at | ✅ | 更新时间 |

### 4.2 预测模型

| 模型 | 说明 |
| --- | --- |
| 基础模型 | 按承运人平均时效 |
| 历史模型 | 基于该航线历史数据 |
| 实时模型 | 综合天气/港口拥堵/中转 |
| AI 模型 | 机器学习预测（高级） |

### 4.3 预测输入

- 历史时效数据（该航线、该承运人）
- 当前船期/航班
- 港口拥堵指数
- 天气数据
- 节假日影响
- 中转港情况
- 海关放行历史

### 4.4 预测输出

- ETA 预测值
- 置信度
- 可能延误预警
- 替代路线建议

### 4.5 ETA 更新策略

- 起运前：基于船期
- 在途中：每日更新
- 异常时：实时更新
- 到港前 24h：每小时更新

## 十二、小结

跟踪与异常是国际物流系统的"客户触点"与"质量保障"。本模块细化的关键：
1. **多源事件采集**：自动+手工，确保完整
2. **智能异常识别**：主动发现，而非被动响应
3. **客户透明可见**：提升信任与体验
4. **ETA 智能预测**：辅助决策与提前预警
5. **异常 SLA**：保障服务质量
6. **多渠道通知**：邮件/短信/微信/WhatsApp 覆盖
